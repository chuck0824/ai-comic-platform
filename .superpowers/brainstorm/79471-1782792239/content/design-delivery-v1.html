设计 4/4：接口、分期与验收

按纵向切片交付，每一期都是可上线闭环，不留下只有页面没有数据的“待接入”入口。

P0

资料闭环

标签、简介、总纲、新旧入口、仓库联动。

  • 拆分旧 TagEditor 单文件
  • 新增项目资料与标签接口
  • 补权限、404、1/3/3/1 校验
  • 旧 /tag-editor/:scriptId 自动兼容
  • 仓库恢复真实列表、标签筛选与编辑入口
P1

设定管理

角色、背景、势力、地点、物品完整 CRUD。

  • 统一设定实体 + 类型化字段
  • 列表、搜索、详情、复制、归档
  • 实体关系与引用保护
  • 版本记录、审计和编辑冲突
  • 导航数量与完善状态实时更新
P2

AI 提取回写

异步提取、证据、差异审核与上下文生效。

  • 按全文/章节/版本创建任务
  • 候选匹配与逐字段三选一
  • 幂等重试、批量确认、事务写入
  • 生成参数快照与下游刷新事件
  • 提取模型、Prompt、证据全链路审计
核心 API 边界
GET /content-projects/{id}/editor
PUT /content-projects/{id}/tags
PATCH /content-projects/{id}/profile
GET|POST /content-projects/{id}/settings
GET|PATCH|DELETE /content-projects/{id}/settings/{sid}
POST /content-projects/{id}/setting-extractions
GET /content-projects/{id}/setting-extractions/{bid}
POST /content-projects/{id}/setting-extractions/{bid}/apply

旧 tags 接口保留并委托同一领域服务，避免两套业务规则。

建议数据表
content_project_profiles — 标签/简介/总纲/版本
project_setting_entities — 五类正式设定
project_setting_versions — 字段级前后值
setting_extraction_batches — 任务与来源版本
setting_extraction_candidates — 候选、证据、决策

标签使用可索引列或规范化关联，不只塞进不可查询 JSON。

验收测试矩阵

层级
关键场景
通过标准
前端单测
标签上限、保存队列、离开保护、差异三选一
竞态下最终服务端值等于最后一次用户选择
后端单测
权限、合法值、404、revision、幂等、事务回滚
越权不可写；非法标签不落库；冲突明确返回 409
集成测试
旧 script 映射、仓库筛选、参数快照、事件刷新
一次确认后所有读取面看到同一版本
E2E
编辑标签 → 筛选命中；AI 提取 → 审核 → 后续生成读取
主路径可完成，刷新/返回后数据与状态不丢失
需要确认：是否批准按 P0 → P1 → P2 实施，并以以上接口边界与测试矩阵作为方案基线？
