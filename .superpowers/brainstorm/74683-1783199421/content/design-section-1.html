第一章：产品边界与核心对象

已选方案：兼容层驱动的分阶段绞杀迁移

当前冲突
  • 项目中心可能长期停留在骨架屏
  • director / reference 节点类型不一致
  • 剪辑、音频处理、合成导出仍暴露在 Canvas
  • 模型硬编码、固定积分、部分接口仍为 mock
  • 导演状态混存在节点 JSON，缺少版本流
  • 节点采用与镜头采用存在双事实源
目标边界
CanvasProject
探索模式 / 正式生产模式
↓
ShotWorkUnit
临时镜头 / 正式 shot revision
↓
六类节点 + 共享 DirectorScene 版本流
↓
请求快照 → 候选 → 正式采用 → 交付清单

必须遵守的规则

  • 空白画布可探索、使用导演台和试生成；正式采用与交付前绑定内容项目和分镜 revision。
  • 节点严格保持文本、图片、视频、音频、脚本、导演台六类；候选、质检、任务不是节点。
  • 每个镜头工作单元共享一个导演台版本流，多个视频节点可复用冻结版本。
  • 冻结导演包和生成请求快照不可变；执行状态只属于 Task/Attempt。
  • ShotAdoption 是正式采用唯一事实源。
  • Canvas 只交付采用镜头、清单、校验和素材包，不做多轨剪辑和成片合成。
  • Seedance 进入开发前必须通过真实供应商 API 合同验证 Gate。
