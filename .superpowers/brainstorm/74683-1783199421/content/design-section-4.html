R0：先解决当前可用性
  • 项目中心请求超时或账户中心异常时，进入可解释错误/最近项目只读态，禁止无限骨架屏。
  • 统一 director 类型；扫描并分类旧 reference 节点。
  • 隐藏分享、通知、批量操作等假入口；移除剪辑和合成入口。
  • 建立新旧 API 契约测试、迁移盘点报告和发布开关。
R1：建立可迁移生产内核
  • 探索/正式生产双模式、ShotWorkUnit、类型端口和连接迁移。
  • 请求快照、候选、节点选择、正式采用和任务中心关联。
  • 拆分 3194 行 Canvas.vue，先抽领域状态，再替换 UI。
  • 单画布升级、备份快照、影子读校验和灰度发布。
R2–R3：导演台与真实生成
  • Three.js 视口、GLB、Gizmo、动作片段、摄影机和单镜头时间线。
  • 机位/动作/灯光材质预设、自动检查、冻结 revision。
  • Blender Worker 隔离执行、坐标转换、输出校验、超时和幂等重试。
  • Seedance 真实 API 合同验证通过后才启用 Adapter；未通过时保持 Provider Sandbox。
R4：质量与外部后期交接
  • 质量问题定位到时间区间和来源节点/轨道。
  • 严重度策略、授权强制采用和审计原因。
  • 固化 ShotAdoption、DeliveryManifest、校验和及素材包。
  • 生成 EDL/FCPXML 和路径映射，不在 Canvas 内做剪辑。

阶段 Gate

  • G0：Seedance 真实 API、限额、回调、计费和内容安全合同验证。
  • G1：资产 GLB 归一化、签名 URL、许可和真人肖像授权可追溯。
  • G2：Blender Worker 镜像版本、资源配额、并发、超时与成本压测通过。
  • G3：生成积分冻结、实扣、部分退还、补偿和对账闭环通过。

主要风险与控制

  • 旧 JSON 形态不可预测：先盘点和影子投影，歧义必须人工确认。
  • Web/Blender 画面不一致：使用黄金场景做坐标、焦段、帧和动作回归。
  • Three.js 性能不足：对象/三角面预算、按需加载、实例化群众和降级预览。
  • 质量模型误判：分级阻断、人工覆盖、记录原因并持续校准。

发布与清理

使用 CANVAS_KERNEL_V2、TYPED_PORTS、DIRECTOR_V2、MODEL_ADAPTER_V2、QUALITY_DELIVERY_V2 分级开关。按 Workspace/Canvas 灰度；升级后新链路单写。连续两个发布周期完成迁移审计且无回滚需求后，才删除旧合成 API、旧导演 mock 和兼容投影。
