V6 PRD 就绪度详细审查

总结论：V4+V5 已把“创作、版本、分镜、画布”的主干想清楚，但当前仍是“产品架构方案”，不是“开发可直接执行的 PRD”。若直接交开发，大概率会出现范围失控、业务口径不一、后端表结构反复迁移、画布同步无法验收。建议先完成 9 个高优先级决策，再生成正式 PRD 和开发同步包。

1. PRD 就绪度评分

85%产品主流程
70%功能覆盖
55%交互可执行
45%技术合同可执行
35%上线与运营准备

已经成立的部分

  • 短剧/长篇/TVC 三模式与上传入口。
  • 流程化创作台，而不是复杂 Tab 工作台。
  • 人物/剧情先行，世界地图渐进构建。
  • 参数、逐集钩子、三智能体、版本和过期检测。
  • A/B/C 分镜 Master、项目插件包和 L0–L4 成熟度。
  • Canvas Import Manifest、半耦合快照和 Agent 生产回路。

仍然阻碍开发的部分

  • 用户、角色、权限和协作边界未定义。
  • P0 范围过大，不具备单期交付可行性。
  • 核心术语、模式切换和 TVC 双入口仍有口径风险。
  • 交互页、异常页、空状态和恢复策略未穷举。
  • 数据字典、API Schema、事件目录和迁移脚本未出。
  • 合规、成本、SLA、数据埋点、灰度发布未定义。

2. 九项高优先级问题：未解决前不建议正式进开发

#问题风险建议结论
H1产品根对象不统一
“剧本、内容项目、源头文本、改编脚本”在不同文档中交叉使用。		表名、路由、权限、交易和画布关联会反复改。产品统一叫“内容项目”；scripts 只作为过渡期物理表名。
H2TVC 两条路径未合并
它既是独立模式，又可从小说/品牌故事改编。		数据结构可能做成两套，无法统一版本和交易。TVC 为独立模式，支持 source_type=brief 或 source_type=content_version，最终都产出 tvc_script_version。
H3角色与权限未定义
编剧、编导、导演、资产制作、审核、企业管理员的权限不清。		锁稿、解锁、审核、导入画布和市场上架可被错误执行。定义 Owner/Editor/Reviewer/Producer/Viewer 项目角色和动作级权限矩阵。
H4P0 超载
三模式、上传、长篇、TVC、三 Agent、A/B/C、画布快照都放在第一期。		开发周期、测试面和迁移风险同时爆炸。按“基础底座 → 短剧纵向切片 → 长篇 → TVC → 生产级画布”分里程碑。
H5流程门禁还是口号
“确认并继续”需要明确每阶段必填、可跳过、可风险放行和解锁规则。		前端、后端和测试会各自理解一套。为每个 Stage 定义 entry_condition、required_tasks、exit_condition、override_permission、next_stage。
H6数据迁移与兼容缺失
现有 scripts/script_episodes/chapter_versions/adaptation_versions/canvas_projects 如何迁移未定义。		上线后历史用户数据丢失，新旧 API 并行失败。提供 schema migration、backfill、双读兼容期、回滚方案和历史数据校验报告。
H7上传与 AI 合规未建立
版权声明、隐私、敏感内容、商业声称、TVC 禁限词未入流程。		用户上传他人作品、AI 输出违规广告、企业机密进入外部模型。增加授权声明、数据分类、模型传输提示、内容审查、TVC claims 证据字段和审计日志。
H8AI 成本与资源控制未设计
批量生成、三 Agent 审核、A→B→C 升档都会大量消耗。		无法做费用预估、限额、二次确认和异常止损。每任务生成前显示预估积分/时间/范围；支持上限、取消、重试成本和团队预算。
H9产品成功标准缺失
当前只有功能验收，没有用户价值和商业结果。		产品上线后无法判断流程变简单了还是更复杂了。定义北极星指标与漏斗：项目启动→首个可用版本→锁稿→分镜→首个采用画布资产→导出。

3. 十项中优先级问题：可进入 PRD，但不能遗留给开发自行决定

M1–M5：用户与交互

  1. 用户画像/JTBD 未按独立创作者、内容团队、TVC 营销团队拆分。
  2. 三模式之间是否可切换，以及切换后哪些参数保留未定义。
  3. 空项目、解析失败、AI 超时、上下文冲突、无权限等异常页缺失。
  4. 自动保存、撤销、并发编辑、离线恢复的交互文案和冲突 UI 未定义。
  5. 新手引导、模板、示例项目和逐步跳过策略未设计。

M6–M10：运行与运营

  1. 平台适配规则需要版本化，不能把抖音/快手/视频号规则写死在 Prompt。
  2. 长上下文的摘要、召回、必选事实和记忆过期策略未定义。
  3. 任务中心、通知、失败重试、部分成功和运维可观测指标缺失。
  4. 上传文件/生成资产的保留期、删除、导出和账号注销策略未定义。
  5. 市场授权包对编辑、改编、生产、导出和二次交易的限制未体现。

4. 五项低优先级，建议纳入设计系统和后续版本

无障碍与可读性

对比度、键盘操作、焦点状态、色弱友好、大文本编辑器可读性。

国际化

TikTok 项目的时区、语言、敏感词、字幕、字数和合规规则。

移动端

移动端是只审核/查看，还是支持编辑，需明确响应式边界。

命名与文案

“剧本、正文、脚本、分镜、锁稿、采用”需建立统一术语表。

用户帮助

阶段解释、为什么需要这项、AI 使用了哪些上下文、修订影响什么。

5. 建议的用户与权限模型

项目角色主要权限不允许
Owner管理成员、锁稿/解锁、画布同步、上架、删除项目企业安全策略另有限制时不得绕过
Editor编辑设定、大纲、正文、改编、分镜；提交审核不能锁定核心资产、上架或删除项目
Reviewer查看版本和 Agent 报告，批准、驳回、风险放行不能静默修改正文
Producer管理插件包、成熟度、画布导入、批量生成、采用和导出不能修改已锁定源正文
Viewer查看、评论、下载授权范围内产物不能编辑、生成、审核、锁定

6. 建议重拆里程碑，不按原 P0–P3 直接开工

M0 底座

内容项目、版本、依赖、生成任务、权限、参数快照、Context Assembler、新旧数据迁移。本阶段不扩大功能。

M1 纵向切片

只打通一条短剧闭环：故事种子→人物→梗概→分集→第 1 集正文→三 Agent→A 档分镜→半耦合导入画布做概念验证。

M2 短剧完整

多集、逐集钩子、批量生成、跨集连续性、投流、项目列表恢复、上传剧本直达。

M3 长篇

剧情任务、总纲/分卷/章节、世界事实、地点 L0/L1、时间线、伏笔、长上下文和连续性。

M4 TVC

简报、品牌/产品档案、创意策略、分秒脚本、TVC 钩子、合规 claims、多时长/多平台改版。

M5 生产

B/C 档、项目插件包、L0–L4、生产准入、ProductionAgent/QualityAgent、批量画布、diff 同步和导出 Manifest。

9. 建议的开发同步顺序

1. 产品决策评审→2. 术语/模型/权限评审→3. 纵向切片交互评审→4. API/ERD/迁移评审→5. 用例与测试评审→6. 排期和开工
不建议先让前端继续堆页面，再让后端猜数据结构。第一个开发会议必须先确认“内容项目、版本、依赖、角色权限、生成任务、Canvas Snapshot”六个基础模型。

10. 最终判断

问题结论
能否形成正式 PRD？可以。V4+V5 已具备主体，需按 V6 的 PRD 章节和高优先级决策补齐。
现在能否直接交开发？不建议。目前可用于方案评审，不足以支撑无歧义开发和验收。
开发同步需要什么？一份主 PRD + 一份技术合同附录 + 一份迁移与测试计划，而不是把历史多份文档一起丢给开发。
✓

认可 V6 审查结论

下一步将 V4+V5 合并为正式 PRD，并按 V6 补齐高优先级决策、开发合同和验收标准。
