剧本创作模块完整重编方案

设计结论：保留现有“快速/精细生成、上传、标签、钩子、审核、改编、分镜、投流、仓库、画布”能力，但不再放在一条 10 步线性向导中。改为 “共享内容项目 + 短剧/长篇双编排 + 派生生产资产”。

1. 用户业务流

短剧快速创作

人物/桥段→选题梗概→分集大纲→逐集正文→审核锁稿

人物、地点、剧情任务由 AI 轻量提取，用户确认即可。世界地图不作为门槛。

长篇世界观创作

人物/桥段→关系与任务→总纲→分卷→逐章正文

世界观、地点、时间线随剧情扩展而渐进完善，不强制一开始建完。

锁稿后的可选去向

继续修订保存/发布改编 AI 漫剧/短剧/网剧/TVC选范围生成分镜生成投流素材导入画布

2. 新页面结构：把向导改成可恢复的项目工作台

内容项目概览创作台设定库大纲与正文审核中心改编脚本分镜脚本投流素材版本记录画布关联

创作台 · 当前任务

短剧模式第 3 集源头版本 v0.8未锁稿

左侧：结构导航

短剧：选题、梗概、分集、单集
长篇：总纲、分卷、章节

右侧：当前内容编辑器

自动保存草稿、手动建版本、AI 续写/润色/扩写/压缩、修订对比、上下文查看。

快速生成仍保留，但生成后直接创建内容项目并进入工作台，不再只展示一个无法恢复的结果卡片。

3. 设定库：人物与剧情先行，世界与地图渐进生长

人物设定

  • 身份、外貌、性格、动机、秘密
  • 短期/长期目标、成长弧
  • 人物关系及关系变化
  • 知识边界：每个人当前知道什么

剧情任务

  • 主线、支线、角色任务
  • 起点、阶段节点、阻碍、代价
  • 完成/失败条件
  • 关联卷、章节、集数和伏笔回收

世界设定

  • 时代、规则、能力/科技体系
  • 势力、文化、禁忌、资源
  • 设定事实可标记“已确认/候选/冲突”
  • AI 生成前只读取已确认事实

地点与地图

  • L0：从桥段自动提取地点卡
  • L1：区域层级、距离、交通、势力关系
  • L2：按需生成世界/区域可视化地图
  • 地点可作为剧情的空间约束

时间线与伏笔

  • 世界历史事件
  • 当前剧情时序与人物行程
  • 伏笔的埋设、提醒、兑现和过期
  • 自动检查时间/空间冲突

标签与钩子策略

  • 保留现有 4 轴标签
  • 增加内容长度、受众、平台、节奏
  • 长篇用阶段大钩子，短剧用单集钩子曲线
  • 钩子与剧情任务、伏笔关联

4. 现有功能迁移矩阵

现有功能处理新位置/新行为
AI 写作 / 用户上传保留统一创建内容项目；上传后自动拆章并提取设定。
快速模式重排变成“故事种子快速启动”，生成后仍可进入项目工作台修订。
精细 10 步向导替换拆为短剧/长篇双编排，改用工作台任务导航，允许回退与跳转。
4 轴标签保留增强作为项目级元数据，所有生成任务共用。
梗概/世界观/起承转合拆分梗概归“大纲”；世界事实归“设定库”；不再混在一个 JSON 里。
角色自动提取前移从剧本后处理改为故事种子后的核心步骤，可编辑、去重、版本化。
分集大纲/单集正文保留重做每集/章独立 ID、内容和版本，不再共用一个 scriptText。
联合审核分阶段正文：钩子+编辑+连续性；改编：钩子+改编+编导；分镜：编导+导演+生产。
改编脚本保留强化必须绑定源正文版本和范围；源文修订后标记 needs_sync。
A/B/C 分镜独立资产进入现有 Storyboard 专业编辑器；支持镜头增删改排、版本和锁定。
投流素材可选资产从指定源正文/改编/分镜版本生成，每条可编辑与采用。
剧本仓库升级改为“内容项目库”，点击编辑必须恢复项目和当前位置。
Prompt 管理保留重构按任务类型+创作模式+内容类型组合，使用结构化输出协议。
画布导入保留收紧只从锁定分镜版本生成快照；画布修改默认不回写 Master。

5. 数据与版本模型

scripts（暂保留为项目根，产品名改为“内容项目”） ├─ creation_mode: short_drama | long_form ├─ story_seeds / story_seed_versions ├─ characters / character_versions / character_relations ├─ plot_tasks / plot_task_links ├─ world_facts / factions ├─ locations / location_relations / map_versions ├─ timelines / foreshadowings ├─ outline_nodes（overall | arc | volume | episode | chapter） ├─ content_units（episode | chapter） │ └─ content_versions ├─ adaptation_versions（强制 source_version_id + source_range） ├─ storyboard_versions / storyboard_shots ├─ promotion_assets ├─ review_reports（artifact_type + artifact_version_id） └─ artifact_dependencies（源版本→派生版本，用于过期检测）

为降低迁移风险，第一期不强制把 scripts 表重命名。先把它当项目根使用，保留现有 ID、交易、标签、画布关联。

6. 生成上下文：确保“用户修订稿”真正进入下一步

Context Assembler

前端只提交任务类型、范围和所选版本 ID。后端统一组装已确认人物、剧情任务、世界事实、地点、前文摘要、本单元大纲和用户修订稿。

Structured Output Contract

topic、synopsis、outline、episode、adaptation、storyboard、promotion 每类任务都有 JSON Schema。解析失败时自动修复一次；仍失败则显式报错，不再用固定示例假装真实结果。

选定源版本→组装上下文快照→AI 生成→Schema 校验→生成新草稿→用户修订/建版本

7. 状态、修订和过期检测

needs_sync
源版本已变更
  • 修改锁稿内容不直接覆盖，而是从锁稿版本分支新草稿。
  • 源正文新建版本后，已有改编/分镜只标记 needs_sync，由用户选择保留、局部同步或重新生成。
  • 地点、人物、任务设定变更时，系统先计算受影响章节，不全局重生成。

8. API 和任务编排

资产 API

/content-projects/{id}
/characters /plot-tasks /world-facts
/locations /outlines /content-units
/versions /dependencies

生成 API

POST /generation-jobs 创建任务
GET /generation-jobs/{id} 查询
POST /generation-jobs/{id}/retry 重试
POST /generation-jobs/{id}/cancel 取消

  • 异步执行从 ScriptGenService 的自调用拆到独立 Executor，避免 @Async 因自调用失效。
  • 任务携带幂等键、输入快照、Prompt 版本、模型和费用；页面刷新仍可恢复。
  • 所有读写 API 统一校验 owner/member 权限，修复现有通过 ID 越权更新的风险。

9. 异常与用户保护

草稿保护

本地草稿 + 服务端自动保存；乐观锁冲突时保留两份并提供对比。

AI 失败

任务保留原始输入和错误；可重试/换模型。生产环境不使用 mock 冒充成功。

上下文过长

使用设定索引、章节摘要和相关性召回；必选事实始终注入，避免人设漂移。

10. 验收与测试

核心验收场景

  • 修改梗概后，大纲必须使用修订稿。
  • 切换集/章时内容独立，刷新后位置和草稿不丢。
  • 人物事实修改后，只标记受影响内容。
  • 改编/分镜能追溯到源版本。
  • 地图不建立也能完成长篇前期创作。

测试类型

  • Context Assembler 单元测试
  • JSON Schema 解析与修复测试
  • 版本依赖/过期判定集成测试
  • 短剧和长篇两条 E2E
  • 权限与并发修改测试
