V5 对照核查：《用户端产品功能设计》模块二 + 画布闭环

核查结论：V4 已覆盖三模式、上传、参数、钩子与三智能体，但对照原方案后仍缺少生产级闭环。主要断点是：分镜 Master 的 A/B/C 结构、项目插件包、资产成熟度、统一 ID、跨章状态、画布快照协议、ProductionAgent/QualityAgent 回路、同步冲突策略。V5 补齐后，链路才能从创作走到可编辑的画布生产结果。

1. 核查问题清单

#位置缺失/冲突严重度V5 修正
1分镜生产V4 只提到 A/B/C，未保留场景目标卡、Beat、导演维度和 C 档生产三表。高定义 Storyboard Master 三层结构与升档规则。
2创作→分镜未纳入项目插件包：人物、声音、场景、道具、风格、伏笔、禁止偏移。高插件包版本成为分镜和画布的必要输入。
3资产准入未定义 L0–L4 成熟度和锁定、降级、连续性复核。高恢复成熟度模型，C 档与批量生产设准入门槛。
4剧集连续性人物伤势、关系、道具位置、伏笔、Voice_ID、场景状态未形成跨章状态表。高新增 continuity_snapshot，作为下一集/章和分镜输入。
5画布导入V4 没有定义导入快照的完整数据合同、映射表、幂等与事务回滚。高定义 Canvas Import Manifest 和 master→snapshot 映射。
6画布同步“弱/半/强耦合”未落到差异检测、冲突处理和回写新版本。高明确半耦合默认，所有同步都需用户确认。
7Agent 闭环V4 有创作三 Agent，但没有 ScriptAgent→ProductionAgent→QualityAgent→画布节点的闭环。高补全生产任务、结果落盘、质检标注和人工采用回路。
8事实源源正文、改编、分镜 Master 和画布镜头谁能覆盖谁不够明确。高每层拥有独立 Master，下游只保存快照和依赖，不自动覆盖上游。
9编辑器未明确拖拽排集、插入/删除集、批量生成、格式校验、情绪曲线、敏感词和台词统计。中并入流程阶段中的专业编辑器功能。
10风险放行用户强行通过审核后，风险未带入分镜和画布。中review_risk_snapshot 随导入快照传递并在问题节点持续提示。
11项目记忆/Skill项目记忆、禁止偏移、Prompt/Skill 版本未与生成快照绑定。中每次生成保存 memory_snapshot_id 和 skill_version_ids。
12交易/购买资产已购剧本进入创作/分镜/画布的授权边界没有体现。中根据授权包决定可编辑、可改编、可生产和可导出范围。
13状态机内容审核状态与交易上架状态被混在同一 status 概念中。中拆为 content_status、production_status、market_status 三条状态轴。
14导出闭环画布生产结果和项目素材包 manifest 未回关联内容项目。中导出 manifest 记录源版本、分镜版本、采用资产与模型参数。

2. 修正后的唯一事实源链

源头正文 Master 版本→改编脚本 Master 版本（可选）→分镜 Master 版本 A/B/C→画布导入快照→画布镜头/节点→生成资产候选版本→采用资产/导出 Manifest

覆盖原则：每一层只修改自己的 Master 或快照。画布修改不自动改分镜；分镜修改不自动改改编；改编修改不自动改源正文。需向上同步时，必须用户确认并生成新版本。

3. 分镜 Master 必须保留的 A/B/C 结构

A 档 · 快速创作

  • 场景戏剧目标卡
  • Beat：进入、试探、升级、反转、钩子
  • 轻量主分镜表
  • 镜头数/时长预算
  • 可进行创作确认，不直接批量生产

B 档 · 导演确认

  • 导演意图
  • 人物行动动机/关系调度
  • 信息差控制
  • 声画关系和剪辑点
  • 关键场景可局部从 A 升到 B

C 档 · 生产交付

  • AI 抽卡表：角色/服装/场景/首帧/构图/光影/img_prompt
  • AI 视频表：首帧/尾帧/动作链/运镜/video_prompt/失败策略
  • 配音字幕表：Voice_ID/情绪/语速/文件/口型
  • 只有 C 档锁定版本可直接进入批量画布生产
便捷例外：A 档可导入画布做概念验证，但画布状态必须标记“非生产快照”，禁止一键批量生产。

4. 项目插件包、资产成熟度与统一 ID

项目插件包

人物设定Face/CostumeVoice世界观场景道具伏笔视觉风格禁止偏移平台/画幅Prompt/Skill 版本

分镜生成和画布导入都必须绑定一个插件包版本。项目设定变化后，不覆盖已有快照。

统一 ID

Project_ID → Episode/Chapter_ID → Scene_ID → Shot_ID；Character_ID → Face_ID / Costume_ID / Voice_ID；Location_ID / Prop_ID / Style_ID / Prompt_ID。稳定 ID 是分镜与画布差异同步的基础。

L0 无资产文字临时锚点
L1 文字设定临时 Character/Location ID
L2 候选参考图片/音频候选版本
L3 已审核允许进入生产
L4 已锁定批量生产不可随意修改

5. 从分镜 Master 到画布的生产准入

准入检查概念验证批量生产不满足时
源正文/改编版本可为 approved 或风险放行必须 locked返回创作台审核/锁稿
分镜档位A/B 可用C 档必须 locked升档并完成生产三表

6. Canvas Import Manifest（画布导入数据合同）

{ "content_project_id": 123, "source_artifact": { "type": "adaptation", "id": 88, "version_id": 901 }, "storyboard": { "id": 55, "version_id": 777, "tier": "C", "locked": true }, "plugin_pack": { "id": 9, "version_id": 31 }, "coupling_mode": "semi", "import_mode": "create | update_diff", "target": { "platform": "douyin", "aspect_ratio": "9:16", "duration_sec": 90 }, "asset_bindings": ["CH_LIN/FACE_LIN_V01", "LOC_OFFICE_V01", "STYLE_KMANGA_V01"], "continuity_snapshot_id": 602, "review_risk_snapshot_id": 710, "shots": ["C档生产字段完整的 Shot Master 快照"], "idempotency_key": "project-storyboardVersion-canvasProject" }

导入结果必须返回：canvas_project_id、canvas_snapshot_id、script_node_id、master_shot_id↔canvas_shot_id 映射、已创建节点数、缺失资产任务、风险提示。整个导入在一个事务中完成；任一必需映射失败则回滚。

7. 画布节点生成与 Agent 生产闭环

ScriptAgent
分镜与生产策略→Canvas Snapshot
脚本节点+镜头映射→ProductionAgent
创建/连接/执行节点→图片/视频/音频候选资产→QualityAgent
质检标注→用户采用/重生成
  • ScriptAgent 不直接写生成结果，只输出分镜与编排任务。
  • ProductionAgent 通过画布 API 创建脚本、角色参考、场景参考、图片、视频、音频节点与连线。
  • QualityAgent 把角色不一致、场景跳变、Prompt 超限、生成失败等标注绑定到节点。
  • 用户选择采用版本后，更新画布快照的 adopted_asset_id，不回写分镜 Master。

8. 耦合模式和差异同步

模式用法源版本变更画布改动
弱耦合纯文本/交易资产，或一次性导出不通知画布永不回写
半耦合（默认）锁定分镜生成独立画布快照标记“有新源版本”，用户手动查看 diff 并选择更新镜头默认只留在画布
强耦合团队协作中需维持 Shot ID 映射自动计算 diff，但应用仍需用户确认可提议回写，确认后生成新分镜版本
冲突规则：同一 Shot 如果在源分镜和画布都被修改，不自动覆盖。差异弹窗展示“保留画布 / 使用新 Master / 复制为新镜头”。

9. 修正后的页面跳转和回路

流程化创作台→正文/改编锁稿→分镜专业编辑器 A/B/C→生产准入检查→创建/更新画布快照→画布生产
↓
采用资产/导出素材包→内容项目概览查看关联结果→源版本变更时查看同步差异→确认后生成新分镜/画布快照版本

10. 三条状态轴，避免概念混乱

内容状态
draft→reviewing→needs_revision→approved→locked
生产状态
not_started→preflight→canvas_ready→generating→quality_review→deliverable
交易状态
private→pending_review→listed→sold→delisted

11. 与当前实现的明确差距

当前前端

canvasApi.importScript(id, scriptId) 只发送 script_id，没有传 source_version、coupling_mode、storyboard_version、plugin_pack_version、shots、asset_bindings 和 review risks。

当前后端

导入服务虽预留 script_id/coupling_mode/source_version/shots，但会默认 source_version=v0.1，且 CanvasProject 只记 script_id，没有 canvas_snapshot_id、storyboard_version_id、plugin_pack_version_id 和镜头映射表。

因此现有“进入画布”只能算创建了脚本节点和镜头记录，还不是可追溯、可同步、可回滚的生产快照。

12. 分期落地调整

P0

保留 V4 的三模式、上传、参数、钩子、三 Agent 和流程化创作台；新增 Storyboard Master 版本、稳定 ID、半耦合快照、Canvas Import Manifest、导入事务与镜头映射。

P1

实现 A/B/C 完整结构、项目插件包、L0–L4 成熟度、跨章连续性快照、生产准入、风险快照与产能/费用预估。

P2

实现 ScriptAgent→ProductionAgent→QualityAgent 画布闭环、节点标注、采用版本、Master↔Canvas diff、冲突处理和确认回写新版本。

P3

强耦合团队协作、项目记忆/Skill 版本快照、购买资产授权准入、导出 Manifest 完整追溯和世界地图生产关联。

13. 新增验收标准

  • 同一分镜版本重复导入不会重复创建镜头或节点。
  • 每个 Canvas Shot 能追溯到 Storyboard Master Shot 和源正文/改编版本。
  • 导入任一必需映射失败时全部回滚，不留半套画布数据。
  • 源分镜变更后可查看镜头级 diff，未修改镜头可批量更新，冲突镜头必须手工决策。
  • 画布修改不自动覆盖分镜 Master；回写确认后生成新分镜版本。
  • C 档批量生产前校验核心资产成熟度、插件包版本、风险和平台/画幅参数。
  • QualityAgent 问题能准确定位节点、镜头和生成资产版本。
  • 导出素材包 manifest 能回溯内容项目、源版本、分镜版本、画布快照和采用资产。
