独立建模，不继续扩张现有 prompt_templates；现有 Skill 与 Agent 会话保持边界，通过执行快照关联。

四、发布与并发规则
  • 草稿必须通过变量、参数 Schema、Prompt 长度和输出样例校验，并至少有一次成功试跑，才能发布。
  • 已发布版本不可原地修改；编辑会创建新草稿。激活历史版本即完成回滚。
  • 发布和项目绑定使用 row_version 乐观锁，防止两位管理员互相覆盖。
  • 删除只允许未被引用的草稿；已发布版本只能归档，历史执行快照永久保留其必要信息。
五、异常处理

允许自动处理

  • 没有用户/项目绑定时使用系统默认版本
  • 模型输出格式错误时按锁定 Schema 修复一次
  • 网络类可重试错误使用原执行快照重试

必须停止并提示

  • 用户配置存在非法变量或越权指令
  • 项目权限、内容 revision 或绑定版本冲突
  • 结构化输出修复后仍不合格
  • 发布版本已归档或模型策略不可用

不能在用户已明确绑定的配置失效时静默切换其他 Agent，否则结果不可解释。此类情况应失败并要求重新选择。

六、旧功能迁移
  1. 盘点剧本、钩子、审核、分镜服务中的硬编码 Prompt，生成四类系统 Blueprint。
  2. 将现有 prompt_templates 中属于四类角色的用户内容迁成 user_agent + v1 草稿；图片、视频类模板保持原状。
  3. 业务服务先接统一 Resolver，并保留系统 Blueprint 作为无绑定时的兼容默认。
  4. 四条业务链路全部验证后，下线旧 PromptManager 的角色配置入口；不删除历史数据。
