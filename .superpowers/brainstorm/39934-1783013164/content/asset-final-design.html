设计确认 4/4：组件、异常处理、测试与交付优先级

目标不是只完成页面，而是跑通“生成任务 → 资产入库 → 项目分类 → 复用/发布 → 回收”的可靠闭环。

一、系统组件边界

前端工作台
AssetHistory 容器
项目树/分类/筛选
记录卡/详情/批量栏
画布/发布/回收弹窗
→
资产应用服务
HistoryQueryService
AssetCommandService
CanvasPlacementService
AssetMigrationService
→
统一数据模型
generation_tasks
workspace_assets
asset_versions
favorites/activity/placements

查询与命令分离：列表筛选不承载写逻辑；移动、删除、发布、画布放置各自有明确事务边界。Controller 只做鉴权上下文、校验和 DTO 转换。

二、关键数据流

1 创建任务
写 Workspace、内容项目、分类、创建人
→
2 异步执行
pending → running
→
3 校验输出
文件存在、元数据完整
→
4 原子入库
asset + version + 节点回写
→
5 标记成功
工作台出现可复用资产

第 3/4 步任一失败时不得标记 succeeded。跨存储和数据库无法单事务时，使用 outbox/补偿任务：文件已上传但数据库失败则延迟登记或清理；数据库成功但节点回写失败则重试回写并展示“处理中”。

三、异常处理矩阵

异常服务端处理页面反馈
列表请求失败/超时记录 request_id，不清空已有成功数据局部错误条 + 重试，保留筛选和列表
请求竞态无额外写入仅采纳最后一次查询序号，旧响应丢弃
版本冲突409 + 当前 row_version提示数据已更新，刷新详情，不覆盖他人修改
文件缺失422/48008；生成修复事件预览区显示“文件不可用”，保留元数据与诊断入口
批量部分失败逐项事务，返回成功/失败明细成功项更新，失败项保留选中并可重试
双击发送画布Idempotency-Key 重放同一 placement只出现一个节点，不重复弹成功提示
发布状态变化409/48006，返回当前 PENDING/APPROVED 等状态刷新发布区，不重复提交审批
生成成功但资产登记失败任务不进入 succeeded；补偿重试并报警显示“结果入库中/失败原因”，允许人工重试登记
Workspace 被切换每次请求重新校验 header取消未完成查询、清空选中项、加载新 Workspace

四、测试矩阵

后端单元测试

分类映射、状态机、allowed_actions、Workspace 权限、重试链、软删除期限、幂等哈希、DTO 映射。

数据库集成测试

H2/MySQL 迁移一致；分页筛选、索引、乐观锁、唯一约束、回填、部分失败、事务补偿。

前端组件测试

URL 状态、项目切换、请求竞态、三类卡片、媒体预览、权限禁用、局部错误、批量结果。

E2E 验收

生成到入库、项目分类、收藏刷新、失败重试、画布幂等、团队审批、删除恢复、越权不可见。

五、强制验收指标

  • 不同剧本/项目资产零混入；无归属资产只出现在未归档区。
  • 跨 Workspace 资产查询、详情、下载、移动、画布和发布全部不可枚举、不可操作。
  • 生成任务 SUCCEEDED 与可用 asset_version 一一对应，验收数据中“成功无资产”数量为 0。
  • 收藏刷新后保持；删除后 30 天内可恢复；已存在画布节点不因资产进回收站失效。
  • 相同幂等键重复发送画布 10 次只创建 1 个节点。
  • 50,000 条 Workspace 数据下，常用列表查询 p95 ≤ 500ms（服务端，不含媒体加载），无全表扫描。
  • 旧 /task-monitor 正确重定向；旧资产接口兼容期有弃用头和调用量监控。

六、交付优先级

阶段范围完成标准
P0 数据可信Workspace ID 统一、canonical 模型、迁移/回填、任务归属、输出校验、补偿机制、权限成功无资产=0，跨 Workspace 越权=0
P1 可用工作台项目树、业务分类、统一任务卡、分页筛选、详情预览、持久收藏、重试/取消、真实发送画布核心日常生产闭环可用，旧 TaskMonitor 合并
P2 管理闭环批量操作、未归档整理、签名下载、回收站、活动日志、个人直发/团队审批资产可整理、可追踪、可发布
后续版本复杂版本树、版权合同、自动内容审核、指纹去重、跨项目依赖图不阻塞本期，不提前建设
