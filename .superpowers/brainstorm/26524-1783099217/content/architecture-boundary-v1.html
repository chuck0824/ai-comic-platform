第一部分：总体架构与边界

统一观察和处置，不把不同业务强行塞进同一个状态机。

任务事件中心
生成域
排队 / 执行 / 资产入库
积分预扣 / 结算 / 退款
交易域
订单 / 支付 / 交付
退款 / 争议 / 卖家结算

冻结 / 转账 / 冲正
账本 / 余额 / 对账结果
↓ 领域事件 + Outbox + 定时拉取兜底 ↓
统一任务投影
Task Case、阶段、时间线、费用、关联对象
操作路由
鉴权、幂等、回源业务服务
治理引擎
SLA、告警、对账、工单、补偿
↓ 同源数据，不同权限与信息密度 ↓
用户任务中心：我的生成 / 我的交易 / 我的费用
运营控制台：全局态势 / 异常队列 / 对账 / 工单

边界原则

  • 生成、订单、钱包仍是各自事实源；任务中心只保存可重建的查询投影和治理记录。
  • 取消、重试、支付、退款、补偿都经操作路由回源执行，不允许直接改业务表状态。
  • 资产工作台继续管理成功产物；任务中心管理过程与费用，两者按 task_uuid / asset_uuid 互跳。
  • 普通用户只能看到当前 Workspace 内有权访问的数据；运营端按独立权限开放敏感财务和补偿操作。
