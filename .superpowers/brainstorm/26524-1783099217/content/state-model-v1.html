第二部分：统一状态模型

一个 Task Case 聚合全过程；顶层统一，域内状态保持精确。

统一顶层状态

待处理
→
进行中
→
成功
失败
已取消
异常待处置

同时独立记录健康度：正常 / 有风险 / SLA 超时 / 数据不一致；“业务失败”和“系统异常”不混为一谈。

生成 Task Case
创建
↓
积分预估与冻结
↓
排队 → 模型执行
↓
输出校验 → 资产入库 → 节点回写
↓
实际费用结算 → 成功
任一阶段失败 → 释放冻结 / 退款
结算或入库失败 → 异常待补偿
交易 Task Case
创建订单 / 企业审批
↓
待支付 → 支付处理中 → 已支付
↓
权益快照 → 内容交付
↓
卖家资金冻结期 → 结算完成
退款申请 → 审核 → 原交易冲正
支付、交付、账本不一致 → 异常待对账

每个 Task Case 必备信息

身份：case_uuid、domain、task_type、Workspace、创建人、关联项目/订单/资产。

状态：summary_status、domain_stage、health_status、progress、current_owner、next_action。

时间：创建、开始、最近事件、阶段截止、完成时间。

财务：预估、冻结、实扣、退款/冲正、币种或积分、账本交易号。

追踪：request_id、trace_id、idempotency_key、重试链、事件时间线。

关键规则

  • “支付成功但未交付”显示为进行中 + 数据不一致，不显示为支付失败。
  • “模型已出结果但资产入库失败”显示为异常待补偿，不提前标记生成成功。
  • 重试创建新执行尝试并挂到原 Task Case，保留完整成本和失败记录。
  • 所有状态来自事件序列，允许重放重建投影；晚到事件按版本号与发生时间处理。
