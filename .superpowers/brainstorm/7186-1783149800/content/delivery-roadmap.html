设计四：三期交付路线与验收门槛

每一期都形成可独立验收的闭环；后一期复用前一期内核，不推翻数据模型。

PHASE 1 · 核心闭环

准入检查 + 返工治理

  • 项目级 SOP 控制台
  • 真实数据上下文与13项规则
  • PASS/WARNING/BLOCKED/NOT_READY/ERROR
  • 不可变报告与检查历史
  • 返工单、责任人、复核状态机
  • 生产准入 Gate 与权限审计
退出条件：发现问题 → 派单 → 修复 → 复核 → 重检 → 放行全链路可用
PHASE 2 · 生产联动

画布质检 + 动作 Gate

  • 画布质检侧栏与节点染色
  • 问题定位到节点/镜头
  • 生图、转视频、采用、导出 Gate
  • 低风险一键修复
  • Prompt/参数修改前确认
  • 报告过期与增量重检
退出条件：任何生产入口都不能绕过 P0/P1 拦截，控制台与画布状态一致
PHASE 3 · 运营增强

失败恢复 + 产能与报告

  • 失败次数与策略状态机
  • 安全自动重试与人工升级
  • 镜头复杂度、工时与风险估算
  • 质量趋势与返工统计
  • 检查报告导出与版本归档
  • 规则效果监控与版本升级
退出条件：恢复动作可追溯，估算口径可解释，管理报表来自真实生产记录
权限边界
制片 / PM：发起检查、分派返工、查看全局、提交版本晋级
导演 / 审核人：复核 P0/P1、确认高风险修改、批准生产版本
生产岗位：查看并处理本人问题、执行安全修复、申请复核
系统管理员：发布规则版本；不参与业务放行
共同限制：任何角色都不能直接篡改检查结果或绕过 P0/P1 Gate
自动化验收
规则单测：每条规则覆盖通过、阻断、待配置、异常
服务集成：快照过期、Gate 矩阵、工单状态、幂等重试
API 契约：字段、枚举、权限和错误码稳定
前端状态：加载、空态、过期、部分失败、无权限
E2E：发现问题 → 定位 → 修复 → 复核 → 重检 → 放行
现有代码处理：Sop.vue 静态数据全部移除；新增前端 SOP API 与状态层；SopController 改为 DTO + 应用服务；现有 SopService 硬编码逻辑拆除；补充数据库迁移、权限校验和前后端契约测试。
