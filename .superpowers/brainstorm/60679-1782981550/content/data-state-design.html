设计 2/4：持久化模型与执行状态机

会话是长期容器；每条用户指令可产生一个版本化计划；计划经审批后才进入执行。

核心数据关系
agent_sessions
workspace / project
owner / status
last_message_at
1 → N
agent_messages
role / content_type
content_json
token / cost
1 → N
agent_plans
version / risk
estimate / status
approval_snapshot
1 → N
agent_plan_steps
tool / mode / inputs
idempotency_key
status / result_ref
agent_executions
每次尝试、耗时、成本、错误、关联 generation_task
agent_events
递增 seq，供 SSE 断线续传与审计时间线
计划生命周期
DRAFT→ AWAITING_APPROVAL→ QUEUED→ RUNNING→ SUCCEEDED
PAUSED：人工暂停/高风险 PARTIAL_FAILED：部分完成，可重试 FAILED：不可继续 CANCELED：用户取消

必须成立的约束

  • 审批绑定 plan_version + inputs_hash + estimated_cost；计划变化后原审批自动失效。
  • 每个写操作步骤都有幂等键，重试不能重复创建节点、任务或扣费。
  • SSE 使用事件序号续传；页面重连先补历史事件，再接实时事件。
  • 消息保存用户可见内容、工具摘要和引用；敏感 Prompt、密钥、隐藏推理不进入前端。
