## 1. 结论与边界

剧本创作保持一个项目、八个创作阶段，场景资产作为项目级共享能力接入小说分析、剧本正文和文字分镜，不增加第九阶段。权威顺序只有一套：创作设置 → 小说上传 → 小说分析 → 改编方案 → 结构化文字剧本 → 剧本正文 → 审核修订 → 文字分镜。

路由职责明确分开：`/script-gen` 是四入口启动台与最近项目列表；`/script-gen/new` 负责新建；`/script-gen/:projectId/workspace` 是具备后端持久化能力的生产原生工作台。静态验收演示 `eight-stage-workbench.html` 只保存当前页会话状态，用于交互确认，非生产事实源，不向后端、Obsidian 文件系统或画布项目写入数据。

场景数据固定划分为四层：场景母资产、场景变体、剧本场景实例、分镜场景快照。前两层用于复用，第三层记录某一剧本场景对具体资产版本的引用，第四层是在分镜锁定时形成的不可变快照。

## 4. 场景四层与版本规则

| 层级 | 稳定身份 | 版本/状态 | 修改规则 |
|---|---|---|---|
| 场景母资产 | `asset_id` + `stable_id` | 生命周期 `ACTIVE` / `DISABLED` / `ARCHIVED`；语义版本 immutable | 名称/标签等管理变更不使消费者过期；空间、视觉语义等变更新建版本 |
| 场景变体 | `variant_id`，归属一个母资产 | 变体版本单调递增；配对可选但 ID/version 必须同时存在 | 新增或编辑场景变体都会 append 一个新的资产版本；编辑该变体时同时递增变体版本 |
| 剧本场景实例 | 稳定 `SCRIPT_SCENE` target key | 固定引用母资产版本及可选变体版本；同步态 `CURRENT` / `STALE` / `PINNED` | 更新新版或保留旧版均需显式决策；更换空间需选择“仅当前场景”或“更新母资产” |
| 分镜场景快照 | shot/version 绑定及 fingerprint | 锁定后 immutable；锁定或 superseded 版本保持 `PINNED` | 母资产后续修改不回写快照；合并镜头要求场景与绑定完全一致 |

新增绑定只能使用 `ACTIVE` 资产。`DISABLED` 可查看但不能新增引用；`ARCHIVED` 只读且不能恢复为新绑定。归档前必须读取权威影响，存在活动引用时返回冲突并引导先替换引用。恢复历史版本会生成新的不可变版本，不覆盖历史。

语义变更后，未锁定且仍引用旧版的消费者标记 `STALE`；引用当前语义版的消费者为 `CURRENT`；已锁定分镜快照始终为 `PINNED`。`ProjectSceneAssetService.syncStatus` 会比较旧版本已存在的母资产字段和变体语义：仅新增一个未被旧消费者引用的变体时，新旧版本可判为语义等价，旧消费者仍为 `CURRENT`，不会仅因资产版本号增加就成为 `STALE`。替换迁移按消费者逐项执行并保留操作结果，不能用一次前端批量改写伪造成功。

## 5. 前后端数据契约

前端内部统一 camelCase，HTTP 边界统一 snake_case；项目工作区资产应用显式携带 `X-Workspace-Id: project_<projectId>`，全局拦截器不得覆盖。关键引用结构如下：

```json
{
  "scene_id": "SCRIPT-SCENE-001",
  "scene_asset_id": 101,
  "scene_asset_version_id": 1004,
  "scene_variant_id": "SCENE-VARIANT-001",
  "scene_variant_version": 3,
  "sync_status": "CURRENT"
}
```

绑定请求使用 `scene_asset_id`、`scene_asset_version_id`、`scene_variant_id`、`scene_variant_version` 和 `scene_override`。服务端解析历史资产版本后生成 `scene_asset_snapshot` JSON；快照对象本身的 DTO 结构如下，前端不能自行制造 fingerprint：

```json
{
  "master": {
    "id": "SCENE-ASSET-001",
    "name": "林野出租屋",
    "version": 4,
    "path": "04-场景资产/SCENE-ASSET-001-林野出租屋.md",
    "fixedProps": {}
  },
  "variant": { "id": "SCENE-VARIANT-001", "name": "雨夜", "version": 3 },
  "sceneOverride": {},
  "continuityRules": [],
  "finalPromptFragment": "雨夜；冷色侧光",
  "fingerprint": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef"
}
```

`scene_asset_snapshot` 是绑定时冻结的历史版本证据；`fingerprint` 是上述规范化 JSON（不含 fingerprint 字段）的 SHA-256。镜头行并没有独立 `snapshot_locked` 列；锁定语义来自所属 `storyboard_version` 的状态。锁分镜前，服务端要求每个镜头的五个绑定字段齐全、快照结构和 fingerprint 可校验，随后锁定 storyboard version；锁定或 superseded 版本在影响视图中投影为 `PINNED`。

场景资产接口根路径为 `/api/v1/content-projects/{projectId}/scene-assets`：

| 方法与路径 | 用途 |
|---|---|
| `GET /api/v1/content-projects/{projectId}/scene-assets` | 按关键词、空间、复用、生命周期、引用筛选 |
| `POST /api/v1/content-projects/{projectId}/scene-assets` | 创建场景母资产 |
| `POST .../scene-assets/from-location` | 从已保存世界观地点转换 |
| `GET/PATCH .../scene-assets/{assetId}` | 详情与新语义版本 |
| `POST .../{assetId}/variants`、`PATCH .../{assetId}/variants/{variantId}` | 创建/更新场景变体 |
| `GET .../{assetId}/markdown` | 获取安全、确定性的 Markdown 投影 |
| `POST .../{assetId}/versions/{versionId}/restore` | 从历史版本生成新版本 |
| `POST .../{assetId}/activate` | 激活资产 |
| `POST .../{assetId}/disable` | 停用资产 |
| `POST .../{assetId}/archive` | 归档资产（存在活动引用时阻断） |
| `GET .../{assetId}/impact` | 获取权威消费者及 CURRENT/STALE/PINNED 状态 |

生成任务使用 `/api/v1/generation-jobs`，通过 `Idempotency-Key` 防止重复创建；读取、取消、采纳、放弃分别为 `GET /{jobId}`、`POST /{jobId}/cancel`、`POST /{jobId}/accept`、`POST /{jobId}/discard`。例如：`POST /api/v1/generation-jobs/{jobId}/accept`。

## 6. 生成候选、模型与积分

### 6.1 模型选择

**当前实现**：原生工作台调用现有 BFF `/api/v1/ai/models`，并在不可用时使用前端本地模型注册表的内置演示模型；`/api/v1/credits/estimate` 与任务中的 `estimated_credits` / `actual_credits` 目前是兼容估算，执行器还会按生成文本长度作粗略估计。这些值只能支持 UI 守卫与展示，不是 3001 的权威模型目录、余额或账务证据。

**目标合同（P0 延期，尚未落地）**：由 3001 提供权威模型目录与价格快照；只有无真实可用模型时才显示演示模型，且仅显式演示模型允许 `0 积分`。真实任务必须完成预冻结/预消费、按实际用量结算和失败/取消退款，并以 3001 流水为账务事实源。

### 6.2 候选生命周期

后端 API 状态严格为 `pending` → `processing` → `completed`，异常终态为 `failed` 或 `cancelled`。UI 进度映射允许把 API `pending` 显示为 `queued`、API `processing` 显示为 `running`，把 `completed` 显示为成功/完成；UI 名称不得回写成 API 枚举。`completed` 只表示服务端已生成隔离的 `candidate` 内容版本，不自动切换当前版本。返回结果包含 `result_version_id`、`actual_credits`、产物引用、差异、错误码和候选处置状态；其中当前 `actual_credits` 是本地估算字段，不是 3001 结算凭据。

采纳/放弃遵循服务端优先：先调用 accept/discard，成功后再更新前端结果。采纳把候选置为 `accepted` 并以生成时基线执行 CAS 切换当前版本；放弃置为 `discarded` 且不改变当前内容。候选隔离要求 candidate/discarded 不进入公开版本列表、恢复或下游生成上下文。同一决定幂等，采纳与放弃并发返回 `IN_FLIGHT_CONFLICT`；基线已变化返回编辑冲突，不能覆盖新内容。

### 6.3 积分闭环

P0 目标积分闭环为：3001 权威预估 → 预冻结/预消费 → 依据实际 Token 与倍率结算 → 失败/取消退款或退回差额。任务、结果、版本、3001 积分流水与审计记录应共享 task ID，Idempotency-Key 与结算单共同保证不重复扣费。该闭环尚未接入当前工作台；不得用本地 registry、`/credits/estimate` 返回值或执行器粗估的 `actual_credits` 冒充已预冻结、已结算或已退款。


兼容已有 Vault 时允许保留原阶段目录编号，但稳定 `artifact_id`、版本 ID、场景/变体/消费者双链必须保持不变；导出服务通过清单映射目录，而不能仅凭目录数字推断业务阶段。场景索引固定路径是 `04-场景资产/00-场景资产索引.md`。

| 变更源 | 直接失效 | 保持不变 | 用户决策 |
|---|---|---|---|
| 创作设置 | 阶段 2–8 当前产物 | 历史版本 | 查看影响、重生成或保留 |
| 小说世界观地点 | 对应场景母资产转换提示及下游引用 | 已锁分镜快照 | 更新资产或保留旧地点 |
| 场景母资产语义版本 | 未锁剧本场景实例 `STALE` | 锁定快照 `PINNED` | 查看差异、升级新版、保留旧版 |
| 场景变体语义版本 | 引用该变体的未锁消费者 | 其他变体与锁定快照 | 升级或保留 |
| 剧本正文 | 审核修订、文字分镜 | 场景母资产 | 重审与重生成 |
| 已审核正文 | 文字分镜 | 旧分镜版本 | 重生成或继续旧版 |

每次改变当前 Markdown 都创建新版本并更新稳定链接；`90-变更影响.md` 记录 stale 来源、受影响消费者和决策；AI 任务另写 `99-生成与计费记录.md`。不保存 API Key、令牌或 3001 管理密钥。

## 9. 页面状态清单

启动台、项目创建、原生工作台、场景资产库/详情、任务进度、生成结果、版本/影响与画布交接均要覆盖：首次空状态、加载态、正常态、网络/服务错误态、权限不足、重试中、项目 `ARCHIVED` 只读、资产 `DISABLED`/`ARCHIVED`、消费者 `STALE`/`PINNED`、任务 `failed`/`cancelled`、候选冲突和页面刷新恢复。缓存降级只允许浏览，不能据此创建新绑定。

## 10. 数据库迁移至 V17

部署顺序必须执行完整 Flyway 链。与本融合直接相关的是：

- `V16__scene_asset_storyboard_snapshots.sql`：为 `storyboard_version_shots` 增加 `scene_asset_id`、`scene_asset_version_id`、`scene_variant_id`、`scene_variant_version`、`scene_asset_snapshot` 五列，并为资产 ID 与资产版本 ID 建立两个索引。锁定状态沿用 storyboard version；fingerprint 位于 `scene_asset_snapshot` JSON，由服务层校验，不是 V16 的独立列或数据库约束。
- `V17__asset_application_target_key.sql`：为 `asset_applications` 增加稳定 `target_key` 及 `(target_type, target_key)` 索引，使 `SCRIPT_SCENE` 不再依赖不稳定数字 ID。

V17 是当前代码事实，不得写成“止于 V16”。MySQL 8 采用普通 `ADD COLUMN` 与 `CREATE INDEX`，依赖 Flyway 的单次版本迁移语义；H2 测试库和 MySQL 基线 schema 同步包含列与索引。

## 11. 错误码与恢复

错误码必须注明来源：后端稳定枚举来自 `ErrorCode.java`；页面动作守卫来自 `scriptWorkbenchModel.js` / `downstreamStageModel.js`；候选并发反馈来自 `generationResultPersistence.js`。只有前者是后端 `BizException` 稳定码，前端动作码不能当成服务端 API 合同。

| 错误码 | 来源 | 说明 | 恢复动作 |
|---|---|---|---|
| `ASSET_NOT_FOUND` / `ASSET_VERSION_CONFLICT` / `ASSET_LIFECYCLE_CONFLICT` | 后端 `ErrorCode.java` | 资产/历史版本不存在、变体版本不匹配或生命周期阻断 | 刷新资产、选择有效版本或激活/更换资产 |
| `PARAM_INVALID` | 后端 `ErrorCode.java` | 空变更、无效快照、锁定前镜头快照不完整等 | 按返回 message 修正请求 |
| `EDIT_CONFLICT` / `GENERATION_BASELINE_REQUIRED` | 后端 `ErrorCode.java` | 当前版本已变化或旧候选缺少生成基线 | 刷新对比或重新生成 |
| `MODEL_REQUIRED` / `POINT_ESTIMATE_REQUIRED` | 前端 `scriptWorkbenchModel.js` | 未选模型或非演示模型缺少正估算 | 返回创作设置；注意估算不是账务凭证 |
| `SCENE_ASSET_UNAVAILABLE` / `SCENE_ASSET_VERSION_REQUIRED` / `SCENE_ASSET_VARIANT_PAIR_REQUIRED` | 前端 `downstreamStageModel.js` | 非活动资产、版本缺失或变体 ID/version 不成对 | 选择 ACTIVE 资产和完整版本 |
| `IN_FLIGHT_CONFLICT` | 前端 `generationResultPersistence.js` | 采纳/放弃决定正在提交 | 等待当前请求并刷新 |
| `MISSING_ASSET` / `VARIANT_MISMATCH` / `STALE_ASSET` / `FIXED_PROP_CONFLICT` | 服务端连续性检查结果 | 镜头绑定或快照问题 | 按 repair 指引重绑或修复覆写 |

所有失败保留原产物和候选结果（安全清理要求删除的未提交候选除外），返回 request/task ID 与可执行恢复动作；不以成功 Toast 代替服务端结果。

## 12. 部署、验证与回滚

部署顺序：备份数据库 → 执行 Flyway 至 V17 → 部署后端 → 验证场景/候选 API 与权限 → 部署前端 → 抽样检查 Obsidian 投影 → 开放入口。验收至少运行场景生命周期 E2E、分镜快照 E2E、候选决策 E2E、Task 4–9 前端合同、Vite 构建和静态原型测试。

回滚先关闭新写入口并等待运行任务终态，再回滚前端和后端。若 V17 已产生稳定 `target_key` 数据，优先保留兼容列，不直接执行破坏性 undo；只有确认旧版本不读取该列、已备份且不存在仅以 target_key 定位的引用时，才按 `V17_undo.sql` 回退。V16 快照列承载锁定证据，存在锁定分镜时不得删除；应用回滚应继续只读这些字段。积分结算和 accepted/discarded 历史不能随应用回滚删除。

## 13. 实施判断

当前生产原生工作台已具备八阶段装配、项目场景资产、V17 稳定脚本场景键、分镜锁定快照、候选隔离与服务端优先决策。“完成并归档”当前实际行为是锁定 storyboard version 并写入本地八阶段完成态，不会把 content project 切换为 `ARCHIVED`，也没有 project archive API 调用。仍需 P0 交付 3001 权威模型目录与积分预冻结/结算/退款、Obsidian 文件真实落盘，以及各阶段尚无安全模型合同的生成适配；适配缺失时页面必须返回明确失败，不能合成成功。静态演示仅用于交互验收，不应作为上述剩余能力已生产落地的证据。
