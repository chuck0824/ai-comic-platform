# 场景资产与剧本创作工作台融合设计

> 日期：2026-08-07  
> 适用范围：`/script-gen` 创作启动首页、`/script-gen/:projectId/workspace` 项目工作台、八阶段静态验收原型  
> 设计基线：`http://localhost:8080/script-gen`、`http://localhost:62096/eight-stage-workbench.html`、`漫剧视频创作平台_PRD.md`

## 1. 背景与目标

当前平台存在两套剧本创作体验：

- `/script-gen` 是正式平台中的创作启动首页，提供 AI 快速创作、AI 专业创作、上传已有文稿和 TVC 创作四种入口。
- `eight-stage-workbench.html` 是功能更完整的八阶段静态工作台，已经覆盖创作设置、小说上传、小说分析、改编、结构、正文、审核、分镜、任务、版本、Obsidian 与积分反馈。

两者职责并不冲突。融合目标不是用工作台替换启动首页，而是把启动首页作为建项入口，把八阶段能力原生接入具体项目工作台。同时补齐目前只存在于“主要地点、剧本场景、镜头地点引用”中的场景资产能力。

本次设计目标：

1. 保留 `/script-gen` 的轻量启动职责。
2. 将八阶段工作台原生融合到 `/script-gen/:projectId/workspace`。
3. 建立项目级场景资产库，支持跨集复用、变体、版本和引用追踪。
4. 打通世界观地点、剧本场景、文字分镜和画布交接。
5. 保持所有业务操作可点击、条件不足有引导、成功后有持久结果。
6. 同步更新静态验收页面和平台相关产品文档。

## 2. 已确认的产品决策

### 2.1 启动首页与项目工作台分工

采用“启动首页 + 项目工作台”方案：

```text
/script-gen
└─ 剧本创作启动首页
   ├─ AI 快速创作 → 创建项目 → 项目工作台
   ├─ AI 专业创作 → 创作设置 → 项目工作台
   ├─ 上传已有文稿 → 创作设置 → 小说上传
   └─ TVC 创作 → 保留现有独立流程

/script-gen/:projectId/workspace
└─ 八阶段剧本创作工作台
   ├─ 1 创作设置
   ├─ 2 小说上传
   ├─ 3 小说分析
   ├─ 4 改编方案
   ├─ 5 结构化文字剧本
   ├─ 6 剧本正文
   ├─ 7 审核修订
   └─ 8 文字分镜
```

`/script-gen` 不承载项目内复杂编辑，避免启动方式、最近项目、阶段工作台和资产管理堆叠在同一页面。

### 2.2 原生 Vue 融合

采用原生 Vue 组件融合，不使用 iframe，也不保留第二套独立业务状态：

- `ScriptCreationHome.vue` 继续承担启动首页。
- `ContentProjectWorkspace.vue` 承载八阶段工作台。
- 静态原型中的阶段导航、操作守卫、进度、结果、任务、版本和积分能力拆分为 Vue 组件及可测试状态模型。
- `eight-stage-workbench.html` 保留为产品验收基准，并同步场景资产能力。

### 2.3 项目级场景资产库

场景资产默认属于当前内容项目，可跨集复用，但不直接跨项目共享。后续如需复用到其他项目，通过“发布到 AI 资产市场”或“复制到项目”实现，本期不建设公共资产库。

场景资产库不是第九阶段，而是项目工作台内的共享能力。

## 3. 场景资产四层模型

### 3.1 场景母资产

定义可跨集复用的稳定空间设定，例如“青桥城中村·出租屋”。

核心字段：

| 字段 | 说明 |
|---|---|
| `scene_asset_id` | 项目内稳定 ID |
| `name` | 场景资产名称 |
| `world_location_ref` | 来源世界观地点 |
| `space_type` | 室内、室外、建筑外观、自然环境、幻想空间、虚拟界面 |
| `reusability` | 主场景、常驻场景、单集场景、临时场景 |
| `reality_type` | 现实、幻想、混合 |
| `layout` | 空间布局和区域关系 |
| `materials` | 建筑、地面、墙面和主要材质 |
| `palette` | 主色和辅助色 |
| `lighting` | 基础灯光设定 |
| `landmarks` | 标志物和识别特征 |
| `fixed_props` | 固定道具和固定位置 |
| `movable_props` | 可移动道具清单 |
| `entrances_exits` | 入口、出口和动线 |
| `continuity_rules` | 连续性锚点与禁止变化项 |
| `reference_images` | 参考图及来源 |
| `generation_prompt` | 基础生成提示词 |
| `negative_prompt` | 基础负面提示词 |
| `status` | 草稿、已确认、已停用 |
| `version` | 当前资产版本 |

### 3.2 场景变体

变体描述同一母资产在不同生产状态下的视觉差异，例如“出租屋·深夜停电版”。

核心字段：

- `scene_variant_id`、`scene_asset_id`、名称和版本。
- 时间、天气、季节和事件状态。
- 灯光、色彩、陈设和环境效果变化。
- 损坏、封锁、节庆、施工等特殊状态。
- 相对于母资产的差异说明。
- 变体参考图、提示词后缀和负面提示词补充。

变体只存差异，不复制完整母资产字段；渲染时由母资产版本和变体版本共同组成最终快照。

### 3.3 剧本场景实例

剧本场景实例是某一集中承担具体剧情目的的叙事单元，例如 `EP01-SC03`。

除现有 `scene_id`、集数、节拍、内外景、时间、人物、目的、正文块和预计时长外，新增：

- `scene_asset_ref`：引用的母资产 ID 和版本。
- `scene_variant_ref`：可选变体 ID 和版本。
- `continuity_state`：进入本场时人物、服装、道具和空间状态。
- `override_note`：仅对本场有效、不回写母资产的临时差异。

剧本草稿允许暂不绑定资产，但在进入文字分镜前必须完成绑定。

### 3.4 分镜场景快照

每个镜头通过 `asset_refs` 锁定场景资产和变体的具体版本。快照至少包含：

- 母资产 ID、名称、版本和 Markdown 路径。
- 变体 ID、名称和版本。
- 本剧本场景的临时覆盖项。
- 人物、服装、道具的关联版本。
- 镜头生成时使用的完整提示词片段。

资产升级不会自动覆盖已经锁定的镜头。用户需要执行“保留旧版、升级新版、查看差异”之一。

## 4. 页面与交互设计

### 4.1 场景资产库入口

在项目工作台提供项目级“场景资产库”入口，不增加主流程步骤。入口应在以下位置可达：

- 项目工作台的共享资源区域。
- 小说分析的“主要地点”。
- 剧本正文的场景编辑器。
- 文字分镜右侧的资产和连续性区域。

### 4.2 场景资产库首页

页面采用资产卡片列表和详情抽屉：

- 搜索：名称、地点、标志物和标签。
- 筛选：空间类型、复用等级、状态、是否被引用。
- 卡片：封面、名称、类型、当前版本、变体数、引用集数、状态。
- 操作：新建资产、从主要地点生成、复制、停用、查看影响。

被引用资产不允许删除，只能停用或创建替代关系。

### 4.3 场景资产详情

详情分为五个页签：

1. 基础信息。
2. 视觉设定。
3. 变体管理。
4. 连续性规则。
5. 引用与版本。

所有保存、变体创建、恢复版本、替换引用操作都必须产生任务、版本和可回访结果，不得只显示 Toast。

### 4.4 八阶段联动

#### 小说分析

- “主要地点”卡片增加“转为场景资产”。
- 已转换地点显示场景资产 ID、版本和状态。
- 地点信息更新时，场景资产进入待对比状态，不自动覆盖用户已编辑的视觉设定。

#### 剧本正文

- “新增场景”增加“引用已有资产”和“创建新资产”。
- 场景标题展示资产名称、变体和锁定版本。
- 只修改剧情目的、人物和正文块时，不回写母资产。
- 修改空间设定时，用户必须选择“仅当前场景”或“更新场景资产”。

#### 文字分镜

- 右侧增加场景资产摘要和版本选择。
- 新增、拆分和合并镜头时复制或合并资产引用。
- 连续性检查增加地点、变体、固定道具、人物状态和镜头轴线。
- 进入画布前必须锁定场景资产版本。

#### 画布交接

- 交接镜头、人物、服装、道具和场景资产快照。
- 交接结果记录场景资产和变体版本，不引用可变化的“最新版本”。

## 5. 状态、版本与影响规则

### 5.1 标准写入流程

```text
操作前置条件检查
→ 创建任务
→ 保存资产或引用
→ 创建 Markdown 新版本
→ 计算下游影响
→ 展示持久结果
```

### 5.2 过期影响

- 母资产或变体发生视觉变化时，关联剧本场景和分镜标记为 `STALE`。
- 只修改资产名称、标签或管理字段时，不标记下游过期。
- 剧本场景的临时覆盖项只影响本场景及其镜头。
- 分镜锁定版本后，资产升级只产生升级建议，不自动覆盖。

### 5.3 归档规则

- 归档项目中的场景资产库只读。
- 搜索、筛选、预览、版本对比和引用查看仍可用。
- 保存、生成变体、恢复版本、替换引用等写操作进入 `PROJECT_ARCHIVED` 条件引导。
- 恢复项目后才能重新编辑。

## 6. Obsidian 文档结构

新增目录：

```text
03-小说分析/
└── 世界观/
    └── 主要地点.md
04-场景资产/
├── 00-场景资产索引.md
├── SCENE-ASSET-001-青桥城中村出租屋.md
└── SCENE-ASSET-001/
    ├── V001.md
    ├── V002.md
    └── variants/
        ├── VAR-001-夜晚停电.md
        └── VAR-002-火灾后.md
06-剧本正文/
08-文字分镜/
90-变更影响.md
91-版本历史.md
```

场景资产 Markdown 需要包含：

- 完整 frontmatter。
- 世界观地点、剧本场景、镜头和画布交接的真实路径双链。
- 当前版本、历史版本和引用状态。
- 母资产与变体的版本锁定关系。
- 参考图只记录合法来源和文件引用，不在静态原型中伪造外部上传结果。

## 7. Vue 融合边界

### 7.1 保留

- `ScriptCreationHome.vue` 的四种启动入口。
- 现有平台侧边栏、顶部工作区、登录态和会员状态。
- 内容项目 ID、项目工作台路由和画布路由。

### 7.2 融合

- 将静态原型的八阶段导航、阶段门禁、生成进度、结果、任务、版本、Obsidian 和积分反馈迁入项目工作台。
- 将纯状态逻辑放入独立 view model/composable，Vue 组件只负责交互和渲染。
- 场景资产状态模型与阶段状态分离，通过稳定 ID、版本引用和影响事件通信。

### 7.3 不做

- 不使用 iframe。
- 不把场景资产库增加为第九阶段。
- 不在本期建设跨项目公共场景资产库。
- 不把静态演示描述为真实文件、模型、画布或资产市场写入。
- 不重构与剧本工作台融合无关的仓库、交易和企业模块。

## 8. 异常与条件引导

| 场景 | 处理 |
|---|---|
| 剧本场景未绑定资产 | 允许保存剧本草稿；进入分镜前阻断并引导绑定 |
| 引用版本过期 | 显示 `STALE`，提供保留、升级和对比 |
| 资产被引用时删除 | 禁止删除，提供停用和替换 |
| 变体生成失败 | 保留母资产和历史版本，生成任务可重试 |
| 项目归档后写入 | `PROJECT_ARCHIVED` 引导，零写入 |
| 地点转资产时已存在同名项 | 提供关联已有、创建新资产和取消 |
| 分镜缺少资产快照 | 阻断画布交接并定位缺失镜头 |
| 3001 无模型或不可用 | 使用明确标识的 0 积分演示模型 |

## 9. 验收标准

### 9.1 路由与入口

- `/script-gen` 保留四种启动方式。
- AI 专业创作和上传已有文稿能够进入统一八阶段工作台。
- 项目继续创作进入真实项目 ID 对应的工作台阶段。
- TVC 创作保持独立流程，不被八阶段短剧流程覆盖。

### 9.2 场景资产

- 可以创建、编辑、停用和恢复场景母资产版本。
- 可以为母资产创建多个变体并查看差异。
- 世界观主要地点可以转为项目级场景资产。
- 剧本场景可以绑定母资产和变体版本。
- 分镜镜头可以查看并锁定场景资产快照。
- 被引用资产不能直接删除。

### 9.3 影响与连续性

- 场景资产视觉变化能够标记关联剧本和分镜 `STALE`。
- 已锁定镜头不会被资产升级自动覆盖。
- 连续性检查能定位场景、变体、固定道具和人物状态问题。
- 画布交接包含场景资产及变体版本。

### 9.4 操作反馈

- 所有显示的业务按钮可点击。
- 条件不足时显示原因、解决办法和定位动作。
- 阻断路径不创建任务、计费、结果或版本。
- 成功路径生成可回访任务、结果和 Markdown 版本。
- Toast 只能作为补充反馈。

### 9.5 测试

- 路由、启动方式和项目工作台跳转测试。
- 场景资产纯状态模型测试。
- Vue 组件交互测试。
- 八阶段与场景资产的跨模块行为测试。
- 静态原型与 Vue 工作台关键操作一致性矩阵。
- 浏览器测试覆盖创建资产、绑定场景、锁定分镜版本、资产升级影响和归档只读。

## 11. 实施顺序

1. 建立场景资产纯状态模型和测试。
2. 完善静态八阶段验收页面中的场景资产体验。
3. 在 Vue 项目工作台中建立八阶段容器和共享状态。
4. 接入场景资产库、剧本绑定和分镜快照。
5. 打通 `/script-gen` 启动入口与项目工作台。
6. 更新 PRD 和相关设计文档。
7. 执行自动化测试、浏览器行为矩阵和视觉验收。
