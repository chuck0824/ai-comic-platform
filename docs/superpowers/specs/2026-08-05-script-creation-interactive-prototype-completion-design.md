# 剧本创作交互原型补全设计

> 日期：2026-08-05  
> 交付形态：可交互静态原型 + 同步更新的剧本创作模块 PRD  
> 视觉基线：`http://localhost:62096/` 当前八阶段静态原型  
> 需求基线：`漫剧视频创作平台_PRD.md`、`剧本创作页面逻辑盘点与补充清单.md`、`/Users/apple/Desktop/未命名文件夹 4/` 产品截图

## 1. 目标与边界

本次迭代把当前“可浏览的八阶段页面”补成“可完整演示创作闭环的静态交互原型”，用于产品评审、研发拆分和验收规则确认。

本次包含：

- 首页、八阶段主流程和阶段完成后的交付动作。
- 阶段准入、真实完成状态和下游过期逻辑。
- 任务、版本、差异、重新生成、异常、检查和导出等通用交互。
- 主要表单、编辑、确认、局部生成和修订动作的浏览器会话级模拟。
- 根据最终原型更新剧本创作模块 PRD。

本次不包含：

- Java/Vue 正式工程改造。
- 服务端接口、数据库、对象存储、SSE/WebSocket 和真实 AI 调用。
- 多人实时协同、真实权限鉴权和真实文件下载。
- 画布视频工作台内部页面。

## 2. 产品流程

主流程固定为：

1. 创作设置
2. 小说上传
3. 小说分析
4. 改编方案
5. 结构化文字剧本
6. 剧本正文
7. 审核修订
8. 文字分镜

内容交付位于第 8 步之后，不占用创作阶段。用户可归档项目、配置导出或送入画布工作台。

### 2.1 入口分支

| 入口 | 初始位置 | 默认状态 |
|---|---|---|
| AI 快速创作 | 创作设置 | `generationMode=快速创作`，保留八阶段但提供“使用推荐配置”快捷动作 |
| AI 专业创作 | 创作设置 | `generationMode=专业创作`，逐阶段确认 |
| 上传已有文稿 | 小说上传 | 使用默认创作设置，上传模式打开；用户可返回第 1 步修改 |
| TVC 创作 | 创作设置 | `creationType=TVC`、`sourceType=品牌叙事`、`targetType=TVC` |
| 继续创作 | 项目记录的当前阶段 | 恢复任务、版本、完成度和待处理问题 |
| 查看详情 | 项目详情抽屉 | 查看项目概览后选择继续、复制、归档或删除 |

### 3.4 阶段流转栏与过渡进度页

第 1—7 阶段底部统一展示固定流转栏：

- `返回上一步`：回到上一阶段，不修改完成状态；第 1 步不展示。
- `保存草稿`：立即触发一次模拟保存并停留当前阶段。
- `确认当前阶段并进入下一步`：执行当前阶段校验，通过后确认产物并打开阶段过渡进度页。
- 当前阶段存在缺失项、活动任务或阻断错误时，确认按钮置灰，并在按钮上方明确列出原因。

阶段过渡进度页是独立的全屏工作区状态，不使用瞬时 Toast 代替。页面包含：

- 当前阶段确认结果、产物版本和确认时间。
- 下一阶段名称、将生成或准备的内容、使用的上游版本。
- `QUEUED`、`RUNNING`、`SUCCEEDED`、`FAILED` 四种状态及已耗时。
- 排队/运行时可取消并返回当前阶段。
- 失败时展示错误原因、请求编号、返回当前阶段和重新尝试。
- 成功后自动开放下一阶段，同时提供 `立即进入下一阶段`；原型倒计时结束后自动进入。

第 8 步不再显示“下一阶段”按钮，流转栏改为：

- `确认并锁定文字分镜`。
- `导出创作包`。
- `送入画布工作台`。

## 4. 原型状态模型

静态原型使用一个统一的前端内存状态对象；刷新后重置为演示初始数据，不写入后端。

```js
const appState = {
  screen: 'home',
  project: {
    id: 'demo-project-1',
    name: '重生后，我在三集内揭开命运系统',
    status: 'IN_PROGRESS',
    activeStage: 0,
    archived: false
  },
  config: {},
  source: {
    mode: 'text',
    state: 'READY',
    file: null,
    chapters: [],
    selectedRange: [1, 50],
    warnings: []
  },
  stages: [],
  tasks: [],
  versions: {},
  staleImpacts: [],
  analysis: {},
  adaptation: {},
  episodes: [],
  reviewIssues: [],
  storyboard: {},
  transition: {
    visible: false,
    fromStage: null,
    toStage: null,
    status: null,
    taskId: null,
    error: null
  },
  notifications: []
};
```

### 4.1 阶段状态

每一阶段使用以下状态之一：

- `LOCKED`：前置条件未满足。
- `READY`：可开始但尚无产物。
- `RUNNING`：当前有生成或解析任务。
- `NEEDS_CONFIRMATION`：已有产物但尚未确认。
- `COMPLETED`：已满足下一阶段准入条件。
- `STALE`：上游已变化，现有产物仍保留但可能过期。
- `FAILED`：本阶段任务失败且暂无可用结果。

左侧导航使用该状态，不再根据当前位置推导“已完成”。完成度按已完成阶段和分集子任务计算。

### 4.2 任务状态

任务状态固定为 `QUEUED`、`RUNNING`、`SUCCEEDED`、`FAILED`、`CANCELED`。静态原型以短定时器模拟状态变化：

1. 创建任务后进入 `QUEUED`。
2. 约 400 毫秒后进入 `RUNNING`。
3. 约 1,200 毫秒后进入 `SUCCEEDED`，并更新阶段产物和版本。
4. 演示失败动作可将任务设为 `FAILED`；失败任务支持重试。
5. 排队或运行任务支持取消。

原型不展示虚假生成百分比，只展示状态、已耗时、范围和操作。

阶段确认任务与内容生成任务分开记录。阶段确认成功后先创建 `STAGE_TRANSITION` 任务；该任务负责校验输入版本、准备下一阶段上下文并更新准入状态，不代表下一阶段内容已经全部生成。

### 4.3 保存状态

可编辑字段统一经过模拟自动保存：

- 输入后显示 `未保存`。
- 300 毫秒后显示 `保存中`。
- 800 毫秒后显示 `已保存` 并记录一个编辑版本。
- “模拟保存失败”入口用于展示失败和重试状态。

## 5. 准入和依赖规则

| 目标阶段 | 准入条件 |
|---|---|
| 小说上传 | 创作设置通过必填校验，或从“上传已有文稿”带默认配置进入 |
| 小说分析 | 小说解析成功或粘贴文本达到 500 字 |
| 改编方案 | 分析包含故事梗概、主角、至少 2 个事件和世界观类型 |
| 结构化文字剧本 | 改编方案已确认且第 1 集已选择高压开场 |
| 剧本正文 | 至少一集结构化剧本通过完整性与时长校验 |
| 审核修订 | 至少一集剧本正文生成成功 |
| 文字分镜 | 对应集剧本没有阻断级审核问题，或阻断问题已修订 |

点击未满足准入条件的阶段时，导航仍可见，内容区显示阻断页面：缺失条件、返回前置阶段、去完成动作，不渲染成功样例数据。

### 5.1 下游影响

| 变更 | 影响 |
|---|---|
| 替换小说或修改确认原文 | 小说分析至文字分镜全部 `STALE` |
| 修改小说分析关键字段 | 改编方案至文字分镜全部 `STALE` |
| 修改改编方案 | 结构化剧本至文字分镜全部 `STALE` |
| 修改某集结构化剧本 | 该集正文、审核、分镜 `STALE` |
| 修改某集正文 | 该集审核和分镜 `STALE` |
| 修订阻断级问题 | 该集分镜回到 `READY` |

变更前必须展示影响范围。用户可以取消、保存并保留旧下游、保存并重新生成下游。

## 6. 核心交互设计

### 6.1 首页与项目管理

- “查看全部/项目列表”打开全部项目页。
- 项目列表支持名称搜索、状态/类型筛选和更新时间排序。
- “查看详情”打开项目详情抽屉。
- 项目详情支持继续创作、复制项目、归档和删除；删除为二次确认，原型中仅隐藏项目并提供撤销提示。

### 6.2 通用阶段流转

- 第 1—7 步均由页面底部统一流转栏完成确认，阶段内部零散的“确认”按钮改为辅助动作或并入流转栏。
- 点击确认时先运行阶段专属校验；失败时停留原页面并滚动到缺失项摘要。
- 校验通过后保存当前版本，将当前阶段置为 `COMPLETED`，然后打开过渡进度页。
- 过渡页以短定时器模拟 `QUEUED → RUNNING → SUCCEEDED`；成功时下一阶段由 `LOCKED` 变为 `READY`。
- 用户取消过渡任务时返回当前阶段；当前阶段保持已确认，下一阶段维持锁定，用户可以再次发起流转。
- 过渡失败不删除当前阶段产物；重新尝试创建新的任务 ID，并保留失败记录。
- 用户从左侧直接点击已开放阶段时可以进入，但不能绕过确认逻辑开放锁定阶段。

### 6.3 小说上传

- 选择文件后进入上传状态，完成后自动进入解析状态。
- 解析成功展示文件名、章节数、有效字数、截取范围、警告和章节目录。
- 用户必须确认有效原文后才能进入小说分析。
- 替换文件时展示下游影响弹窗。
- 提供演示入口切换格式错误、文件过大、内容不足和解析失败。

### 6.4 小说分析

- 故事梗概支持编辑和重新生成。
- 事件支持新增、编辑、删除和上下移动；删除被引用事件时展示影响提示。
- 章节大纲支持搜索、展开和折叠。
- 人物卡支持查看详情；“查看全部”打开完整人物列表；人物字段可编辑保存。
- 世界观四个页签均可进入编辑态。
- “确认分析结果”执行完整性校验，缺失项以列表展示。

### 6.5 改编方案

- 卖点分析包含核心机制、人物卖点、情绪基调和视觉奇观。
- 高压场景候选以可选择卡片展示；第 1 集必须选择一个，第 2、3 集可独立选择。
- 策略字段和自定义规则可编辑；规则支持新增、删除和排序。
- “确认改编方案”保存不可变快照并开放结构化剧本。

### 6.6 结构化剧本

- 分集列表显示 `未生成/生成中/待确认/已完成/失败/已过期`。
- 选择集数进入单集编辑，编辑开场、故事梗概、核心内容、结尾钩子和节拍。
- 节拍支持新增、删除、排序和时间编辑。
- 时间段重叠、倒序或最后结束时间不等于目标时长时阻止确认。
- 支持重新生成本集和仅重新生成节拍。

### 6.7 剧本正文

- 左侧按集和场景导航；中部编辑结构化内容块；右侧切换人物、事件、世界观和上游节拍。
- 场景支持新增、复制、删除和排序。
- 内容块支持动作、对白、旁白、画外、字幕、音效、VFX 和转场。
- AI 工具对当前选区或场景生成可见的“修订建议”预览，用户确认后写入正文。
- “检查剧本”生成可定位的错误、警告和建议；阻断错误进入审核修订。

### 6.8 审核修订

- 支持按严重程度、集数、类型和处理状态筛选。
- 选择问题显示来源位置、原文、原因、修改建议和修订编辑框。
- 用户可接受建议、人工修改、忽略非阻断项或批量处理同类问题。
- 阻断问题全部关闭后，用户可确认该集通过并开放文字分镜。
- 前后差异通过通用版本差异弹窗展示。

### 6.9 文字分镜和交付

- 左侧按集/场景/镜头导航；中部支持表格和卡片视图；右侧显示人物、服装、地点、道具和来源正文。
- 镜头支持新增、复制、删除、排序、拆分和相邻合并。
- 镜头编辑覆盖景别、角度、运镜、构图、画面、角色、对白、情绪、音效、VFX、资产引用、正负提示词和连戏说明。
- 连续性检查定位时长、覆盖、人物/服装/道具/方位和提示词问题。
- 导出配置支持当前集/选中集、版本和 XLSX/JSON/Markdown。
- 创建画布项目前显示资产和版本交接摘要。

## 7. 异常与边界状态

每个阶段至少可演示以下状态：

- 首次进入空状态。
- 前置条件未满足。
- 任务排队、运行、失败、取消、成功。
- 局部任务成功、局部任务失败。
- 保存失败、版本冲突和本地草稿恢复提示。
- 产物过期和下游影响。
- 项目归档只读。
- 内容安全阻断。

所有错误必须同时包含：错误名称、用户可读说明、请求编号、主操作和次操作。

## 8. 视觉与组件约束

- 保留现有深色全局导航、白色步骤栏、浅灰工作区、白色卡片和紫色主操作。
- 不增加新的视觉语言，不改变主导航宽度和八阶段信息架构。
- 抽屉宽度按内容分为 420、560、720 像素三档；复杂编辑使用主内容区，不塞入窄抽屉。
- 主操作每个页面最多一个；危险操作使用红色文字按钮并二次确认。
- 状态不得只靠颜色表达，必须包含文字或图标标签。
- 可编辑控件必须有可见标签、焦点态、禁用态和校验说明。

## 9. 技术设计

继续使用单文件 HTML/CSS/JavaScript，不引入构建工具或第三方框架。

为避免逻辑继续堆叠，脚本内部按职责分区：

1. 演示数据与状态常量。
2. 状态选择器和校验函数。
3. 页面渲染函数。
4. 抽屉/弹窗渲染函数。
5. 动作分发器。
6. 任务和自动保存模拟器。
7. 交互绑定与初始化。

所有按钮使用 `data-action` 进入统一动作分发，避免为每个页面散落独立事件绑定。表单使用 `data-model` 写入状态并触发自动保存。

## 12. 验收标准

本次交付通过需要同时满足：

1. 首页和八阶段均有完整可见页面，不再只有摘要卡片。
2. 阶段准入、完成、失败和过期由状态决定，不由当前索引决定。
3. 所有主要按钮产生页面、面板、状态或提示反馈。
4. 至少可完整演示一次“设置—上传—分析—改编—结构—正文—审核—分镜—导出”。
5. 任务、版本、差异、重新生成、下游影响和异常恢复均可演示。
6. 第 1—7 阶段均有统一确认流转按钮，并能演示过渡页的排队、运行、成功、失败、取消和重试。
7. 第 8 步使用锁定、导出和画布交接动作，不出现不存在的下一阶段。
8. PRD 与最终原型的页面名称、步骤顺序、字段和交互一致。
9. 自动化检查通过，浏览器控制台无错误，关键状态截图齐全。
