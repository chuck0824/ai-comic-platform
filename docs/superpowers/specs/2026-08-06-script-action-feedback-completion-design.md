# 剧本创作全按钮可点击与条件反馈补充设计

> 状态：已确认（方案 B）
> 日期：2026-08-06
> 适用页面：八阶段剧本创作工作台

## 1. 问题与目标

现有页面虽已为大部分按钮配置 `data-action`，但此前的自动化验收主要检查按钮和处理器是否存在，没有验证点击后的可见结果、数据持久化和版本变化。部分 AI 操作依赖正文块选择并直接使用 HTML `disabled`，条件不足时浏览器不会派发点击事件，用户感知为“无反应”；另有少量完成操作仅显示短暂提示，没有结果页面或可复查记录。

本次统一采用以下验收口径：

- 页面中展示的业务按钮始终可点击。
- 条件不足时打开明确的条件提示弹层，不静默失败。
- 条件满足时进入真实编辑、生成、确认、导出或交付流程。
- 成功操作必须至少产生一种可复查结果：内容变化、状态变化、版本记录、任务记录、积分记录或结果页面。
- 不能仅以 Toast 作为生成、确认、导出、归档和画布交付的唯一反馈。

## 2. 统一交互架构

### 2.1 Action Guard

在现有 `dispatchAction(action, element)` 前增加统一动作守卫。守卫根据动作返回：

```text
ALLOW
BLOCKED + reason + requiredAction + targetStage/targetElement
```

`BLOCKED` 时打开“操作前需要完成”弹层，展示缺失条件、原因和下一步按钮。例如：

- 正文 AI 工具未选择正文块：提示“请先选择正文块”，提供“返回正文并高亮可选正文块”。
- 拆分/合并镜头未选择镜头：提示“请先选择镜头”，提供“返回分镜并进入镜头选择状态”。
- 审核通过存在未解决 HIGH/BLOCKER：列出阻断问题并提供“去处理问题”。
- 确认改编方案未选择高压开场：提供“选择高压开场”。

业务按钮不得使用原生 `disabled` 隐藏条件反馈。仅“撤销”等无业务下一步且没有历史记录的辅助按钮允许保留禁用态，但需通过说明文本解释。

### 2.2 Action Result

生成、确认、导出、归档和画布交付统一使用结果弹层，至少显示：

- 操作名称与成功/失败状态；
- 影响的产物、Markdown 路径和新版本号；
- 关联影响数量；
- AI 任务的模型、预计积分、预扣积分、实际积分和返还积分；
- “查看产物”“查看任务”“继续下一步”之一。

## 3. 分阶段行为

### 3.1 小说分析

| 操作 | 条件不足 | 成功结果 |
|---|---|---|
| 编辑梗概 | 无 | 打开编辑器；保存后更新故事梗概 Markdown、版本和影响清单 |
| 新增事件 | 无 | 打开事件表单；保存后事件列表立即新增并更新 Markdown |
| 人物详情 | 无 | 打开人物库；可进入人物编辑并保存人物独立文档 |
| 编辑世界观 | 无 | 打开完整世界观编辑器并保存地点、规则、势力等字段 |

### 3.2 改编方案

选择高压开场打开候选选择弹层，不再默认静默选择第一项。确认方案前校验高压开场和改编规则。重新生成遵循模型配置、积分确认、百分比进度、结果对比和采纳流程。

### 3.3 结构化文字剧本

打开单集结构、新增节拍均进入可编辑弹层。重新生成节拍和当前产物进入统一生成流程；生成完成先展示差异，用户采纳后才写入新版本。

### 3.4 剧本正文

续写、增强冲突、精简对白、改写语气、角色一致性检查在未选择正文块时打开条件提示。选择后进入 AI 差异页。新增场景和正文块保存后立即出现在正文中。检查和导出显示独立结果页。重新生成当前产物不得只创建任务，必须展示生成结果与版本变化。

### 3.5 审核修订

筛选弹层保存条件并更新问题列表。局部修订更新正文和审核记录两个版本。版本对比展示真实修订内容。审核通过受 HIGH/BLOCKER 状态守卫控制。重新生成显示新审核结果、分数变化和积分流水。

### 3.6 文字分镜与交付

新增镜头打开编辑器；拆分、合并在未选择镜头时提示并引导选择；切换视图立即改变页面；连续性检查显示逐项结果。完成并归档、配置导出、创建画布项目均需确认和结果弹层。重新生成文字分镜进入统一生成流程并保留旧版本。

## 4. 生成流程

```text
点击生成
→ Action Guard
→ 选择模型、范围和临时指令
→ 展示预计 Token / 预计积分
→ 用户确认
→ 百分比进度（QUEUED / RUNNING / SUCCEEDED / FAILED）
→ 结果差异
→ 采纳：写入新版本、Markdown、影响与积分记录
→ 放弃：保留任务记录，不修改当前产物
```

演示模型固定 0 积分；真实模型遵循 3001 原生 quota 规则，`1 quota = 1 积分`。

## 5. 错误与恢复

- 条件不足：不创建任务，不扣积分，展示条件提示。
- 生成失败：保留旧内容，显示错误、任务编号和重试入口。
- 保存失败：编辑内容保留在弹层，禁止关闭后丢失。
- 重复点击：同一动作只创建一个活动任务。
- 页面刷新：从任务和产物状态恢复，不依赖内存中的 Toast。

## 6. 测试与验收

测试从“静态存在性”升级为“行为结果”测试：

1. 每个用户列出的按钮执行真实点击。
2. 条件不足时断言条件提示弹层可见，且提示内容准确。
3. 条件满足时断言目标编辑器、配置页或结果页可见。
4. 保存后断言页面内容、产物版本或状态发生变化。
5. AI 操作断言生成配置、进度、差异、采纳和积分流水完整。
6. 导出、归档和画布交付断言出现可复查结果，不以 Toast 作为唯一结果。
7. 覆盖六个阶段的全部列出操作，并在 `localhost:62096` 使用浏览器逐项回归。

验收通过标准：所有展示中的业务按钮可点击；条件不足均有明确反馈；条件满足均完成其声明的业务动作；页面控制台无未处理错误；自动化测试与浏览器行为矩阵全部通过。
