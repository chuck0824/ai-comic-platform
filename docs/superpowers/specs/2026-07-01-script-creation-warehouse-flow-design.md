# 剧本创作与剧本仓库业务流转重构设计

日期：2026-07-01

状态：已完成方案确认，待规格复核

范围：剧本创作入口、剧本仓库、内容项目详情、旧剧本兼容及下游业务准入

## 1. 背景与问题

当前页面职责与用户认知相反：

1. `/script-gen` 同时承担旧版创作流程、V7 升级提示和内容项目列表入口，实际混合了创作、仓库和兼容说明三类职责。
2. `/warehouse` 只展示升级提示并跳转到内容项目列表，不具备仓库应有的查询、筛选、归档、版本和流转管理能力。
3. 用户同时看到“剧本”“内容项目”“V7 项目”“旧版创作”等概念，无法判断它们的关系。
4. 旧 `scripts` 与新 `content_projects` 并存，前端入口和业务规则尚未统一。
5. 内容审核状态、分镜/画布生产状态和交易状态存在混用风险，单一状态无法准确表达项目进度。
6. 仓库对象点击后的去向不稳定，创作、资料编辑、分镜和画布之间缺少一个明确的流转枢纽。

本次采用“统一内容项目 + 模块职责重构”方案，不只交换两个页面，也不在本轮重建完整内容中台。

## 2. 已确认的产品决策

1. 剧本仓库收纳全部项目，包括草稿、审核中、已锁稿、生产中、已完成和已归档项目。
2. 剧本创作首页采用轻量创作启动台，提供新建方式、最近创作和待办提醒，不承担完整项目管理。
3. 前台只展示一套“剧本/作品”概念。数据主对象统一为 `content_project`，不再向用户暴露“V7 项目”和“旧版创作”。
4. 旧剧本自动映射到新版内容项目，旧表和旧接口只作为兼容层存在。
5. 仓库卡片默认进入剧本详情页；“继续创作”必须是显式操作。
6. 剧本详情页承担仓库与创作、分镜、画布、交易和导出的流转枢纽职责。

## 3. 目标与非目标

### 3.1 目标

1. 让“创作”负责启动与续作，让“仓库”负责全生命周期管理。
2. 统一项目主对象、入口、详情和状态规则，消除新旧数据的前端分叉。
3. 将内容、生产和商业状态拆开，避免状态互相覆盖。
4. 使送审、锁稿、分镜、画布和上架操作都绑定明确版本并可追溯。
5. 保证旧剧本在统一仓库中只出现一次，并能进入统一详情和工作台。

### 3.2 非目标

1. 不在本轮重做创作工作台内部的全部写作能力。
2. 不重做画布生产、交易市场或 AI 资产市场本身。
3. 不实现多人实时共编。
4. 不允许新旧两套业务页面长期并行维护。
5. 不允许上游更新自动覆盖既有分镜、画布或交易版本。
6. 本轮不实现版本差异对比界面，仅通过 `blocked_reason` 提示存在可同步版本。

## 4. 信息架构

### 4.1 剧本创作

```text
剧本创作
├─ 新建剧本
│  ├─ AI 快速创作
│  ├─ AI 专业创作
│  ├─ 上传已有文稿
│  └─ TVC 创作
├─ 最近创作（最多 5 个）
└─ 待办提醒
   ├─ 待继续
   ├─ 待审核
   └─ 审核驳回待修改
```

创作启动台只提供进入创作所需的最小信息。它不提供批量归档、复杂筛选、删除、商业状态管理等仓库能力。

### 4.2 剧本仓库

```text
剧本仓库
├─ 全部
├─ 草稿
├─ 审核中
├─ 已锁稿
├─ 生产中
├─ 已完成
├─ 已归档
└─ 回收站
```

仓库支持关键词、类型、来源、内容状态、生产状态、商业状态和更新时间筛选，并提供卡片/列表视图、排序、分页、批量归档与恢复。

### 4.3 剧本详情

```text
概览 | 正文与版本 | 设定资料 | 审核记录 | 分镜 | 生产关联 | 商业记录
```

详情页顶部展示项目名称、类型、更新时间、三轴状态、当前采用版本和唯一主操作。概览页展示完整流转轨迹：

```text
创建 → 创作 → 审核 → 锁稿 → 分镜 → 画布 → 完成/上架
```

## 5. 主流程

```text
创作启动台
→ 新建或续作
→ 创作工作台
→ 保存项目草稿
→ 提交明确版本审核
→ 审核通过或退回修改
→ 确认锁稿
→ 剧本详情
→ 分镜 / 画布生产 / 上架交易 / 导出
```

核心规则：

1. 项目创建成功后立即属于仓库，不存在额外的“保存到仓库”动作。
2. “保存”只保存当前草稿，不改变项目归属。
3. 创作完成后进入项目详情，而不是仓库列表。
4. 仓库卡片点击统一进入详情；显式按钮用于继续创作。
5. 最近创作只展示 5 个项目，并按最后编辑时间排序。
6. 新建、上传和 AI 生成失败时，不得产生伪成功项目或用示例内容替代真实结果。

## 6. 状态模型

### 6.1 三轴状态

| 状态轴 | 状态 | 说明 |
|---|---|---|
| 内容状态 | `draft` → `reviewing` → `needs_revision` / `approved` → `locked` | 表达正文与审核进度 |
| 生产状态 | `not_started` → `storyboarding` → `canvas_producing` → `completed` | 表达分镜和画布生产进度 |
| 商业状态 | `not_listed` → `listing_review` → `listed` → `delisted` | 表达市场上架进度 |

> **内部 `market_status` 到公开 `commercial_status` 映射：**
>
> | 内部存储值 | 公开显示值 | 说明 |
> |---|---|---|
> | `private` | `not_listed` | 未提交上架 |
> | `pending_review` | `listing_review` | 上架审核中 |
> | `listed` | `listed` | 已上架 |
> | `sold` | `listed` | 已售出仍显示为已上架（商业状态不因单笔交易回退） |
> | `delisted` | `delisted` | 已下架 |

项目生命周期独立设置为：

```text
active → archived
```

`lifecycle_status` 仅取 `active` 和 `archived` 两个值。进入回收站后的软删除通过 `isDeleted` 标记实现（MyBatis-Plus 软删除机制），不占用 `lifecycle_status` 列。仓库通过独立的“回收站”视图展示 `isDeleted = 1` 的项目。

### 6.2 状态规则

1. 编辑正文时只更新当前草稿；若项目处于 `approved` 或 `locked`，必须从采用版本派生新草稿，不覆盖旧版本。
2. 提交审核必须绑定 `content_version_id`。审核中的版本不可被原地修改。
3. 审核通过不等于锁稿；锁稿由具备权限的用户单独确认。
4. 正式制作分镜、导入画布或上架必须使用已锁稿版本。
5. 上游产生新版本时，下游状态保持不变，并提示存在可同步版本及差异。
6. 归档不删除版本、审核、分镜、画布和交易记录。
7. 已上架项目不得直接进入回收站；必须先下架再归档。
8. 非法状态迁移由服务端拒绝，前端不能通过直接写状态绕过规则。

### 6.3 主操作映射

| 当前情况 | 主操作 |
|---|---|
| 草稿 | 继续创作 |
| 待审核 | 查看审核进度 |
| 需修改 | 处理审核意见 |
| 已通过 | 确认锁稿 |
| 已锁稿且未生产 | 制作分镜 |
| 生产中 | 查看生产进度 |
| 已完成 | 查看成果或导出 |

商业操作放入详情页商业记录区域或“更多”菜单，不与内容主操作争抢视觉优先级。

## 7. 页面交互

### 7.1 创作启动台

顶部展示四种启动方式：AI 快速创作、AI 专业创作、上传文稿和 TVC 创作。

下方展示：

- 最近编辑的 5 个项目；
- 待处理审核意见；
- 未完成或失败后可重试的生成任务。

最近项目仅提供“继续创作”和“查看详情”。重命名、复制、归档等管理操作统一在仓库或详情完成。

### 7.2 仓库列表

仓库顶部提供搜索、筛选、排序、视图切换和新建入口。项目项展示：

```text
《项目名称》
短剧 · AI创作
内容：待修改
生产：未开始
商业：未上架
更新于：2小时前

[继续创作] [更多]
```

交互约束：

1. 点击卡片主体进入详情页。
2. “继续创作”进入项目最后一个可编辑阶段。
3. “更多”包含重命名、复制、导出和归档。
4. 不在卡片上平铺分镜、画布、上架等下游操作。
5. 批量操作首期只包含归档与恢复，避免高风险批量删除。批量端点：`POST /api/v1/content-projects/batch-archive`、`POST /api/v1/content-projects/batch-restore`。

### 7.3 剧本详情

详情页必须提供：

- 当前采用版本及其审核、锁稿信息；
- 草稿与采用版本差异提示；
- 分镜 Master 与来源版本关系；
- 画布快照、生产进度和最近同步状态；
- 交易记录、上架状态和许可信息；
- 下一推荐动作及不可执行原因。

当操作不满足业务准入条件时，按钮保持可点击并返回结构化引导，例如“请先锁定一个审核通过的内容版本”；无权限操作可以隐藏或呈只读，但服务端仍需独立鉴权。

## 8. 路由设计

| 路由 | 页面职责 |
|---|---|
| `/script-gen` | 创作启动台 |
| `/script-gen/new` | 新建/上传向导 |
| `/script-gen/:projectId/workspace` | 创作工作台 |
| `/script-gen/:projectId/edit/:section?` | 作品资料与设定编辑 |
| `/warehouse` | 统一剧本仓库 |
| `/warehouse/:projectId` | 剧本详情 |

兼容规则：

1. `/script-gen-legacy` 不再展示独立旧版页面，通过 `/api/v1/content-projects/legacy-scripts/{scriptId}/resolve` 解析后重定向到 `/script-gen/:projectId/workspace`。
2. `/tag-editor/:scriptId` 通过兼容解析服务映射到内容项目后，重定向到 `/script-gen/:projectId/edit/tags`。
3. 旧书签和历史链接必须保留可达性，但不得继续产生第二套页面和业务规则。

## 9. 数据与服务边界

`content_projects` 是唯一项目主表，关联：

```text
内容项目
├─ 项目资料与设定
├─ 正文版本
├─ 审核记录
├─ 锁稿版本
├─ 分镜 Master
├─ 画布快照
└─ 交易记录
```

后端职责拆分：

1. `ContentProjectService`：项目元数据、生命周期、列表与详情摘要。
2. `ProjectLifecycleService`：内容状态迁移、准入校验与推荐动作。
3. `ContentVersionService`：草稿、送审、采用、锁稿和版本派生。
4. `LegacyProjectProjectionService`：旧 `scriptId` 与内容项目的幂等映射。
5. `ProjectAccessService`：权限校验，供生命周期和生产服务调用。
6. `ProjectProductionGate`：锁稿版本准入校验，供分镜和画布控制器调用。
7. 分镜、画布和交易服务继续管理各自状态，只向项目详情提供关联摘要。

前端不得分别拉取旧 `scripts` 和新 `content_projects` 后自行合并。列表统一由内容项目接口返回。

## 10. 接口设计

### 10.1 查询接口

```text
GET /api/v1/content-projects
GET /api/v1/content-projects/{id}
GET /api/v1/content-projects/{id}/summary
GET /api/v1/content-projects/recent
GET /api/v1/content-projects/todos
```

列表接口支持：

- `keyword`；
- `creation_mode`；
- `source_mode`；
- `content_status`；
- `production_status`；
- `commercial_status`；
- `lifecycle_status`；
- `updated_from`、`updated_to`（本期可选）；
- `sort`、`page`、`page_size`。

列表项必须包含三轴状态、当前采用版本、最后阶段、下一推荐动作和迁移异常标记，避免前端进行状态推断。

### 10.2 动作接口

状态迁移使用动作接口：

```text
POST /api/v1/content-projects/{id}/submit-review
POST /api/v1/content-projects/{id}/approve
POST /api/v1/content-projects/{id}/request-revision
POST /api/v1/content-projects/{id}/lock
POST /api/v1/content-projects/{id}/archive
POST /api/v1/content-projects/{id}/restore
POST /api/v1/content-projects/{id}/duplicate
```

服务端必须校验项目修订号、目标版本、权限、当前状态、下游依赖和幂等键。不得保留允许前端提交任意状态字符串的新接口。

## 11. 旧数据迁移

1. 为每个未映射的 `scripts` 记录创建或复用对应 `content_projects` 记录，并写入 `legacy_script_id`。
2. 迁移脚本必须可重复执行，同一旧剧本只能对应一个内容项目。
3. 新项目列表只查询 `content_projects`，旧数据通过已建立的映射自然进入列表。
4. 旧接口先解析内容项目，再委托新版服务；过渡期可回写旧投影字段，但不得复制状态规则。
5. 无法迁移的旧项目在仓库标记“数据待修复”，记录原因并禁止重复创建兼容项目。
6. 迁移完成前后分别校验记录数量、所有权、版本数和重复映射。

## 12. 权限与审计

1. Owner/Editor 可继续创作和提交审核。
2. Reviewer 或被授权 Owner 可批准、退回和锁稿。
3. Producer 可基于锁稿版本制作分镜或进入画布生产。
4. 只有 Owner 可归档、恢复和管理商业状态。
5. Viewer 只读。
6. 提交审核、批准、退回、锁稿、解锁、归档、恢复、导入画布和上下架均写入审计日志，并绑定操作版本。

前端按钮可按权限隐藏或禁用，但服务端必须独立执行权限校验。

## 13. 异常与冲突处理

1. 存在未保存内容时，离开或切换项目必须拦截。
2. 出现乐观锁冲突时，展示双方修改时间，允许重新加载或另存新版本。
3. 审核中继续编辑时创建新草稿，不改变送审版本。
4. 锁稿后继续编辑时，从锁稿版本派生新草稿。
5. 下游已有分镜或画布时，上游更新只展示差异并请求确认，不自动覆盖。
6. AI 生成失败时保留输入、任务和错误信息，允许重试，不回退为示例成功数据。
7. 迁移失败时显式显示修复状态，不静默创建重复项目。
8. 无权限、版本失效或准入不足时，接口返回稳定错误码和可展示的用户说明。

## 14. 验收标准

### 14.1 交互验收

1. `/script-gen` 只展示启动方式、最近项目和待办，不展示完整仓库列表。
2. `/warehouse` 能管理全部项目状态，且项目卡片主体统一进入详情。
3. 所有新建项目创建后立即能在仓库检索到。
4. 页面不再出现“V7 项目”“旧版兼容模式”等面向用户的分叉术语。
5. 项目详情始终只有一个基于当前状态计算的主操作。

### 14.2 功能验收

1. 旧剧本在统一仓库只出现一次，并可进入统一详情和创作工作台。
2. 内容、生产、商业三轴状态独立变化，互不覆盖。
3. 非法状态迁移被后端拒绝。
4. 送审版本、锁稿版本、分镜 Master 和画布快照能够完整追溯。
5. 搜索、筛选、排序、分页、归档恢复和权限隔离正确。
6. 刷新或重新登录后能恢复正确项目、阶段和草稿。
7. 上游更新不会静默覆盖下游版本。
8. 迁移脚本重复执行不会产生重复项目。

### 14.3 测试范围

- 前端路由与导航契约测试；
- 创作启动台视图模型测试；
- 仓库筛选、分页和主操作映射测试；
- 状态机单元测试与非法迁移测试；
- 版本送审、锁稿和派生集成测试；
- 旧数据幂等迁移测试；
- 项目权限与工作区隔离测试；
- 剧本创建至画布快照的核心 E2E 测试。

## 15. 建议实施切片

1. **切片一：入口归位。** 将内容项目列表迁入仓库，建立创作启动台和项目详情骨架，调整路由与导航。
2. **切片二：状态与版本。** 落地三轴状态、动作接口、主操作计算、送审和锁稿准入。
3. **切片三：旧数据统一。** 完成幂等迁移、兼容解析和旧路由重定向。
4. **切片四：下游闭环。** 补齐分镜、画布、交易关联摘要与差异提示。
5. **切片五：管理完善。** 增加批量归档、恢复、复制、导出和完整审计。

每个切片必须同时包含前端、后端、数据迁移、权限和测试，不交付只有页面没有真实业务规则的入口。

## 16. 八阶段原生工作台与场景资产补充（2026-08-11）

### 16.1 路由职责

`/script-gen` 是四入口启动台、待办和最近项目列表；`/script-gen/:projectId/workspace` 是生产原生项目工作台。`/warehouse` 仍负责全量项目治理，不与启动台重复。静态验收演示只保留当前页状态，非生产后端、仓库状态或 Obsidian 落盘事实源。

项目的权威八阶段顺序为：创作设置 → 小说上传 → 小说分析 → 改编方案 → 结构化文字剧本 → 剧本正文 → 审核修订 → 文字分镜。仓库的 current stage、恢复入口和主操作必须使用上述 key；旧 `content`、`review`、`import_review` 仅在兼容层归一化，不能回写为新口径。

### 16.2 场景资产与仓库状态

场景资产是项目级共享资源，四层按顺序为：场景母资产、场景变体、剧本场景实例、分镜场景快照。项目归档时保留四层历史、stable ID 和 immutable version；归档项目只读且不能新增资产、绑定、生成候选或画布项目。

场景母资产生命周期 `ACTIVE` / `DISABLED` / `ARCHIVED` 与项目生命周期相互独立。新绑定只允许 ACTIVE；语义版本变化后剧本消费者可为 `CURRENT`、`STALE` 或 `PINNED`；已锁或 superseded 分镜快照始终 PINNED。资产归档前必须先读取权威消费者并处理替换，不能仅根据前端计数放行。

### 16.3 版本、候选和积分投影

生成任务使用 `queued` / `running` / `completed` / `failed` / `cancelled`。completed 产生隔离 candidate 而不是自动切换当前版本；服务端采纳后才成为 accepted，放弃成为 discarded。仓库项目卡片和详情只投影当前公开版本，不把 candidate/discarded 当作当前内容。

模型优先读取 3001 真实可用模型，只有无可用模型或接口不可达时展示内置演示模型；仅显式演示模型为 0 积分。真实任务沿用 3001 现有积分规则：预估 → 预冻结/预消费 → 实际结算 → 退回差额；仓库审计显示 task、`result_version_id`、`actual_credits`，幂等重试不重复扣费。

Obsidian 项目库增加 `04-场景资产/00-场景资产索引.md`，用稳定 asset/version/variant/consumer 链接连接剧本与分镜。生产数据库迁移事实到 V17；静态演示中的归档、导出和交接结果不得投影为仓库真实状态。详细合同见 [`../../剧本创作模块_场景资产与八阶段融合说明.md`](../../剧本创作模块_场景资产与八阶段融合说明.md)。
