# 8080 与 3001 统一账户、模型及计费设计

## 1. 目标

将 `http://localhost:3001/`（new-api）建设为平台唯一的账户、组织权限、模型、API Key、余额和账单事实源；`http://localhost:8080/`（AICP 漫剧平台）作为主要业务操作入口，通过 API 操作同一份数据。

用户也可以直接登录 `3001` 操作。无论从 `8080`、`3001` 还是第三方工具发起模型调用，身份、权限、限额、余额和账单结果必须一致。

## 2. 已确认的原则

1. 不采用账号、企业、权限、余额、模型或 API Key 的双系统存储和双写。
2. `3001` 是账号、个人空间、企业空间、企业成员、角色、余额、API Key、模型目录、模型价格和账单的唯一事实源。
3. `8080` 只保存漫剧项目、剧本、画布、生成任务和资产等业务数据。
4. `8080` 可引用 `3001` 返回的 `user_id`、`workspace_id`、`api_key_id` 和 `request_id`，但不复制账户中心数据。
5. 用户优先在 `8080` 完成日常操作，降低操作成本；直接登录 `3001` 完成相同操作也被支持。
6. `8080` 可短时缓存只读展示数据，但缓存不能作为鉴权、限额或扣费依据。

## 3. 领域模型

### 3.1 用户与空间

- `User`：唯一自然人身份，由 `3001` 管理。
- `Workspace`：计费和权限上下文，类型为 `personal` 或 `enterprise`。
- `WorkspaceMember`：用户在某个空间中的成员关系，包含角色、权限、状态和限额。
- `BillingAccount`：空间对应的统一余额池，由 `3001` 管理。
- `ApiKey`：模型调用凭证，归属一个空间，并标记实际使用成员和用途。

每个注册用户自动拥有一个个人空间，并担任该空间所有者。用户加入企业时新增企业成员关系，不覆盖个人身份。一个用户可以加入多个企业空间，并通过当前空间决定数据范围、模型权限、API Key 和扣费账户。

### 3.2 个人用户

个人用户在个人空间中就是个人主账号：

- 充值进入个人空间余额池。
- 个人空间内的 `8080` 调用和第三方工具调用共同扣减该余额。
- 个人 API Key 归属个人空间。

### 3.3 企业与子账号

企业空间的所有者或企业管理员是企业主账号，企业成员是子账号：

- 主账号充值进入企业统一余额池。
- 所有子账号通过各自 API Key 消费企业统一余额。
- 子账号没有独立钱包。
- 主账号可以给每个子账号设置单日限额、单月限额、模型白名单或黑名单，并可以禁用其 API Key。
- 默认不设置成员消费限额，但仍受企业余额和企业级模型权限约束。
- 成员退出企业或被禁用时，其企业 API Key 立即失效，个人空间及个人 API Key 不受影响。

部门、角色和企业成员关系均由 `3001` 保存。`8080` 不维护其副本。

## 4. API Key 设计

第三方工具统一使用 API Key 调用 `3001`。

每个 API Key 至少关联：

- `workspace_id`
- `member_user_id`
- 用途：`aicp_internal` 或 `external_tool`
- 允许使用的模型范围
- 单日及单月限额
- 状态、创建时间、最后使用时间和撤销时间

`8080` 内部调用使用服务端管理的内部 API Key，不向浏览器返回明文。第三方工具 API Key 可在 `8080` 或 `3001` 创建、撤销和轮换，仅在创建时展示一次明文。

在任一入口进行的 API Key 操作都直接写入 `3001`，另一入口查询时读取同一结果。

## 5. 双入口交互

### 5.1 8080

`8080` 是漫剧平台用户的主要操作入口，应提供：

- 登录和退出
- 个人/企业空间切换
- 余额与用量摘要
- 充值与账单查询
- 企业、部门、成员和角色管理
- 子账号模型授权和消费限额
- API Key 创建、撤销和轮换
- 当前空间可用模型和价格展示

这些页面通过 `8080` 后端的账户中心适配层调用 `3001` API，不直接访问 `3001` 数据库，也不写入本地账户表。

### 5.2 3001

用户可以直接登录 `3001` 进行相同的账户、企业、余额和 API Key 操作。普通用户只能访问自己的空间数据；企业管理员可以管理所属企业；平台管理员可以管理渠道、模型目录和模型价格。

`3001` 中的修改对 `8080` 立即生效，反向亦然。

## 6. 服务边界

### 6.1 3001 负责

- 注册、登录、Token 刷新、会话校验和密码管理
- 个人空间和企业空间
- 企业成员、部门、角色和权限
- API Key 生命周期
- 模型目录、能力、渠道和价格
- 余额、充值、预扣、结算、退款和账单
- 成员日/月限额及模型权限检查
- 统一模型网关和上游供应商调用

### 6.2 8080 负责

- 漫剧项目、剧本、分镜、画布、资产和业务任务
- 生成参数编排和结果回写
- 账户中心功能的用户界面
- `3001` API 的业务适配和错误转换
- 保存 `3001 request_id` 与本地生成任务的关联

`8080` 不负责计算权威余额、维护模型价格、签发 API Key 或执行最终扣费。

## 7. 模型调用与计费流程

1. 用户在 `8080` 选择当前个人或企业空间。
2. `8080` 从 `3001` 获取该空间的可用模型、权限、余额和费用预估。
3. 用户提交生成操作，`8080` 创建漫剧业务任务和全局幂等请求号。
4. `8080` 携带当前用户、空间、成员和幂等请求号调用 `3001`。
5. `3001` 校验 API Key、成员状态、模型权限、日/月限额和共享余额。
6. `3001` 预扣预计费用并调用上游模型。
7. 调用成功后，`3001` 按实际用量结算；调用失败或取消时执行退款。
8. `3001` 返回统一 `request_id`、任务状态、实际用量、实际费用和模型结果。
9. `8080` 保存业务结果以及 `3001 request_id`，不生成独立的权威账单流水。
10. 第三方工具通过 API Key 直接调用 `3001`，遵循相同的权限、限额和余额规则。

`3001` 的余额与账单同时包含 `8080`、`3001` 直接调用和第三方工具调用产生的消费。

## 8. 数据一致性

- 账户中心写操作只允许写入 `3001`。
- `8080` 不直接连接 new-api 数据库，所有交互必须经过受版本控制的 API。
- `8080` 的展示缓存设置短有效期，并在写操作成功后主动失效。
- 鉴权、模型授权、余额和限额每次调用均由 `3001` 实时校验。
- 所有生成请求使用全局唯一幂等键；同一幂等键不能重复预扣或结算。
- `3001 request_id` 是跨系统追踪和账单核对的关联键。

## 9. 错误处理

- `3001` 不可用时，`8080` 禁止发起真实模型生成并显示明确错误。
- 禁止在真实调用失败后静默返回 Mock 结果或将任务标记为成功。
- 余额不足、成员被禁用、模型无权限、API Key 失效和限额超出必须使用稳定错误码。
- `8080` 将稳定错误码转换为用户可操作的中文提示，同时保留 `request_id` 供排查。
- 异步任务支持状态查询、超时、取消和退款状态核对。
- 对无法确认结算状态的请求先查询 `3001`，不得直接重复提交。

## 10. 迁移方案

1. 在 `3001` 增加个人/企业空间、成员关系、角色、限额和空间级 API Key 能力。
2. 定义并版本化供 `8080` 使用的账户中心 API。
3. 将现有 `8080` 用户、企业、部门和成员关系一次性迁移到 `3001`。
4. 生成旧用户、企业 ID 到 `3001` 新 ID 的迁移对照，仅用于业务表外键转换和审计。
5. 将 `8080` 业务数据中的用户和企业引用转换为 `3001` 标识。
6. 完成数据量、成员关系、权限和余额核对后切换登录与鉴权入口。
7. 停止并移除 `8080` 的账户、企业和计费写接口。
8. 删除 `8080` 静态模型目录、固定积分估算和失败自动 Mock 成功逻辑。
9. 迁移结束后禁止账户数据双写，旧表转为只读审计归档并按保留策略下线。

迁移执行必须提供可回滚切换点；回滚只允许在正式切换前进行，正式切换后以 `3001` 为唯一事实源。

## 11. 验收标准

### 11.1 身份与空间

- 同一账号可以登录 `8080` 和 `3001`。
- 用户始终保有个人空间，并可加入多个企业空间。
- 切换当前空间后，数据范围、角色、模型权限、API Key 和扣费账户同步切换。
- 用户退出企业后企业 API Key 立即失效，个人空间不受影响。

### 11.2 企业共享余额

- 企业主账号充值后，所有有效子账号可以消费统一余额。
- 子账号不形成独立钱包。
- 单日限额、单月限额、模型权限和 Token 禁用均能阻止不合规调用。
- 不同成员的用量可以独立统计并归集到企业总账单。

### 11.3 双入口一致性

- 在 `8080` 创建、撤销或轮换 API Key 后，`3001` 立即显示相同结果。
- 在 `3001` 修改成员、权限、余额或 API Key 后，`8080` 立即读取最新结果。
- 任一入口均不会产生第二份账户、权限或计费记录。

### 11.4 模型与计费

- `8080` 展示的模型、价格、余额和权限均来自 `3001`。
- `8080` 与第三方工具的消费共同扣减所属空间的统一余额。
- 成功调用按实际用量结算；失败调用完成退款。
- 相同幂等请求重试不会重复扣费。
- 本地业务任务可以通过 `3001 request_id` 对应到唯一调用与账单记录。

### 11.5 故障行为

- `3001` 不可用时，`8080` 明确阻止真实生成。
- 不出现 Mock 结果冒充真实成功的情况。
- 用户可根据错误提示处理余额、权限、限额或 API Key 问题。

## 12. 非目标

- 不在 `8080` 复制 new-api 的渠道路由和供应商配置功能。
- 不为每个企业子账号创建独立余额钱包。
- 不按 `8080`、第三方工具或其他应用隔离余额。
- 不允许 `8080` 直接修改 `3001` 数据库。
- 不在本设计阶段修改漫剧业务流程、画布交互或资产模型。
