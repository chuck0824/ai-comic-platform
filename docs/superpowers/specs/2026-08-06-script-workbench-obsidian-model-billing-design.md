# 剧本创作工作台交互、Obsidian 文档与模型计费一体化设计

> 日期：2026-08-06  
> 状态：待用户书面确认  
> 范围：现有八阶段静态演示页、项目 Markdown 产物、模型选择与费用展示

## 1. 目标

补齐剧本创作八阶段内所有当前无响应或仅弹提示的操作，使每次编辑、AI 生成、审核和流转都能形成可恢复的页面状态与 Markdown 产物。项目文档按 Obsidian 多文件知识库管理；模型优先同步 `http://localhost:3001` 的真实可用模型，无模型或接口不可用时展示内置演示模型；真实生成沿用 3001 的 Token、倍率、预扣与结算体系。

## 2. 方案比较

### 方案 A：单一大 Markdown 文件

- 优点：文件少，导出简单。
- 缺点：人物、事件、单集正文和分镜无法独立版本化；修改影响范围只能粗粒度标记；多人或多任务写入冲突大。

### 方案 B：按八阶段拆分文件

- 优点：结构清楚，容易对应页面阶段。
- 缺点：人物、事件、章节和单集仍聚集在大文件中，无法精确更新一个实体。

### 方案 C：按阶段与实体拆分的 Obsidian 项目库（采用）

- 优点：人物、事件、章节、单集、场景、镜头均可独立保存、链接、版本化和标记影响；适合 Obsidian 双链与属性查询。
- 代价：需要文档索引、稳定 ID、依赖图和原子写入规则。

用户已确认采用方案 C。

### 3.1 通用 Frontmatter

```yaml
---
project_id: PRJ-001
artifact_id: CHAR-001
artifact_type: character
stage: novel_analysis
status: confirmed
version: 3
updated_at: 2026-08-06T11:30:00+08:00
updated_by: user
source_versions:
  - SOURCE-001@2
depends_on:
  - "[[02-小说原文/第001章]]"
affects:
  - "[[04-改编方案]]"
  - "[[05-分集结构/EP-001-单集结构]]"
stale: false
---
```

稳定 ID 不随文件改名改变。Obsidian 链接供用户阅读和导航，`depends_on`、`affects` 与版本号供系统判断变更影响。

### 3.2 核心文档内容

- `故事梗概.md`：一句话卖点、完整梗概、主线目标、核心冲突、开端/发展/高潮/结局、未解决悬念。
- `主要事件.md`：事件 ID、名称、摘要、关联章节、参与人物、地点、前置事件、后续事件、冲突类型、情绪、重要度。
- `章节大纲.md`：章节 ID、标题、章节摘要、关键事件、人物变化、伏笔、节奏、对应改编集数。
- `世界观.md`：整体世界类型与时间、主要地点、力量体系与规则、禁忌与代价、势力阵营、专有术语。
- `人物/*.md`：身份、角色功能、外形、性格、欲望、恐惧、秘密、能力、边界、人物关系、成长弧、服装/道具/表情锚点、出场章节与事件。
- `改编方案.md`：目标、卖点、高压开场候选及选中项、改编规则、删改合并说明、集数与节奏策略。
- 单集结构、正文、审核、分镜文件均记录所引用的人物、事件、世界观和上游版本。

## 4. 页面交互补全

### 4.1 小说上传

- 粘贴文本最大 2000 个汉字；按 Unicode 汉字计数，标点、数字和拉丁字符同时计入总字符提示，但汉字超过 2000 时阻止继续输入。
- 文本框右下角显示“汉字 0/2000 · 总字符 0”。
- 超限粘贴只保留前 2000 个汉字对应的完整文本片段，并提示已截断；空内容不能确认。
- 保存后更新原文索引与对应章节 Markdown，并创建新版本。

### 4.2 小说分析

- 编辑梗概：打开可编辑抽屉，保存后更新 `故事梗概.md`，创建版本并显示影响确认。
- 新增事件：打开事件表单，生成稳定事件 ID；保存后更新 `主要事件.md`。
- 人物详情：进入人物资产抽屉，可查看、新增和编辑完整人物小传；保存到独立人物文件。
- 编辑世界观：按整体、地点、力量体系、阵营四类编辑并更新 `世界观.md`。
- 任一变更均计算改编方案、分集结构、正文、审核和分镜的影响范围。

### 4.3 改编方案

- 选择高压开场：候选项可单选，展示选中理由、预估节奏与预计费用。
- 新增改编规则：新增可编辑规则行，支持类型、内容、优先级和删除。
- 确认改编方案：校验已选择开场且至少一条规则，保存 `04-改编方案.md` 快照。
- 重新生成：先选模型、范围和临时指令，显示预估 Token/费用，确认后创建任务和新版本。

### 4.4 结构化文字剧本

- 打开单集结构：打开集级编辑抽屉，展示目标、冲突、转折、结尾钩子与节拍。
- 新增节拍：在选中位置插入节拍并进入编辑状态。
- 重新生成节拍：仅替换指定范围，旧版本保留；生成前显示模型与费用预估。
- 保存后更新对应 `EP-NNN-单集结构.md` 并标记正文及后续产物状态。

### 4.5 剧本正文

- 正文编辑器支持选中正文块；“续写、增强冲突、精简对白、改写语气、角色一致性”对选中块生效。
- 未选中内容时 AI 工具禁用并说明原因。
- 新增场景、新增正文块形成真实结构数据；正文块类型可选择。
- 运行检查产生可定位问题列表；导出正文打开格式与范围配置并生成文件。
- 所有 AI 修改先进入差异预览，用户采纳后写入正文 Markdown 新版本。

### 4.6 审核修订

- 筛选问题支持严重级别、集数、规则类型和状态。
- 保存局部修订创建正文新版本，并使原审核结果失效。
- 对比修订前后展示文本差异和影响清单。
- 存在未关闭的 BLOCKER/HIGH 时禁止通过；全部关闭后可审核通过并写入审核文件。

### 4.7 文字分镜

- 新增、拆分、合并镜头直接修改镜头结构，并支持撤销当前操作。
- 卡片/表格切换保留选择与滚动位置。
- 连续性检查形成角色、地点、服装、道具和轴线问题列表。
- 完成并归档写入项目主页状态；配置导出打开格式配置；创建画布项目生成交接摘要。
- 重新生成仅作用于当前集、场景或镜头范围，保留旧版本并记录费用。

## 5. 变更影响与同步修改

### 5.1 依赖图

```text
创作设置 → 小说原文 → 小说分析 → 改编方案 → 分集结构 → 剧本正文 → 审核修订 → 文字分镜
                         ↘ 人物/事件/世界观被正文与分镜直接引用 ↗
```

系统不自动覆盖所有下游内容。保存上游变更后：

1. 对比修改前后的实体 ID、字段和版本。
2. 根据依赖图找出直接与间接受影响文件。
3. 将受影响文件标记 `stale: true`，写入 `90-变更影响.md`。
4. 页面展示“需同步修改”清单，用户可逐项选择：人工修改、使用模型同步修改、保留旧版并注明理由。
5. AI 同步修改必须先显示差异预览；用户采纳后创建新版本，绝不静默覆盖。
6. 所有关联项处理完成后，`stale` 才能恢复为 `false`。

### 5.2 精确影响示例

- 修改人物姓名：影响人物文件、引用该人物的事件、分集结构、正文和分镜文本字段。
- 修改人物外形：默认仅影响正文视觉描述与分镜资产锚点，不强制重生成事件。
- 修改力量规则：影响引用该规则的事件、冲突解决方式、正文动作和连续性检查。
- 删除主要事件：影响章节大纲、改编方案、关联集节拍、正文与分镜。

## 6. 模型获取与选择

### 6.1 数据源优先级

1. 请求 3001 提供的可用模型接口；正式实现由同源后端代理转发认证，浏览器不保存或暴露管理端密钥。
2. 成功且有数据：展示真实模型名称、供应商、能力、上下文长度、可用分组和价格。
3. 成功但为空或请求失败：展示内置演示模型，并明确标记“演示模型，不产生真实费用”。
4. 后台模型恢复后，用户点击刷新或下次打开选择器时自动切换为真实模型；已进行中的任务继续使用任务快照中的模型。

### 6.2 选择范围

- 项目默认模型：创作设置中选择，供后续阶段默认继承。
- 阶段模型：每个阶段可覆盖项目默认模型。
- 单次模型：重新生成或 AI 局部编辑时可临时覆盖，不改变默认值。
- 每个任务记录 `model_id`、展示名、供应商、模型版本、价格快照、分组倍率和提示词模板版本。

## 7. 统一计费

- 真实模型请求必须通过 3001 的统一 API 网关，不在剧本系统内另建费用算法。
- 创建任务前读取模型价格与分组倍率，按估算输入、最大输出计算预估额度并展示。
- 任务开始按 3001 规则预扣；成功后依据实际输入/输出 Token、模型倍率、完成倍率、缓存与分组倍率结算，多退少补。
- 失败或取消按 3001 现有规则返还未消费额度。
- 演示模型费用固定显示 `¥0（演示）`，不调用结算接口。
- `99-生成与计费记录.md` 只记录非敏感账单快照：任务、操作、模型、Token、倍率、预估、实扣、状态、时间和产物版本；不保存 API Key。

计费记录示例：

```markdown
| 任务 | 操作 | 模型 | 输入/输出 Token | 预估 | 实扣 | 状态 | 产物 |
|---|---|---|---:|---:|---:|---|---|
| TASK-1024 | 重新生成第 1 集节拍 | model-a | 3200 / 860 | 0.42 | 0.39 | 已结算 | [[05-分集结构/EP-001-单集结构]]@V4 |
```

## 8. 状态、错误与恢复

- 页面写入采用“内存草稿 → 校验 → 新版本 → 原子写文件 → 更新索引”的顺序。
- 写文件失败时保留页面草稿，不修改有效版本，并提供重试。
- 模型列表失败不阻断人工编辑；AI 操作使用演示模型，但必须标识不会生成真实生产结果。
- 生成失败保留原文档和旧版本；任务记录失败原因，可重新生成。
- 同一产物保存携带基础版本，版本冲突时禁止覆盖并提供差异比较。

## 9. 验收标准

1. 用户列出的所有按钮均产生可见、可验证、可恢复的状态变化，不再仅显示无后续结果的提示。
2. 小说粘贴文本最多 2000 个汉字，计数、截断和空值校验正确。
3. 小说梗概、事件、章节、世界观、人物、改编方案、单集结构、正文、审核和分镜均可生成对应 Markdown。
4. 修改上游内容后，受影响文件被准确标记并可逐项同步修改；未确认前不覆盖旧版本。
5. 3001 有模型时显示真实模型；无模型或不可用时显示明确标记的内置演示模型。
6. 所有真实 AI 请求使用 3001 的统一计费结果，页面和计费 Markdown 可追溯到任务及产物版本。
7. 八阶段确认按钮、百分比过渡页和返回流程保持可用。
8. 自动化测试覆盖动作绑定、文档结构、依赖状态、模型回退和计费记录；浏览器逐阶段验证核心交互。

## 10. 本轮实现边界

- 静态演示页实现完整可操作状态、演示模型回退、Markdown 预览/下载和真实模型列表的读取适配。
- PRD 补充正式服务所需的 Obsidian 文档服务、依赖图、模型代理和计费接口契约。
- 不在静态页面中嵌入 3001 管理员密钥，不直接修改 3001 的模型、价格或用户余额。
