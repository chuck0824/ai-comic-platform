# 阶段流转百分比加载页设计

> 日期：2026-08-06  
> 状态：待用户评审  
> 适用范围：阶段 1→2 至阶段 7→8 的全部流转

## 1. 目标

将当前信息较多的阶段过渡页简化为单一加载进度百分比页面。用户确认当前阶段后，只需感知“系统正在进入下一阶段”及完成比例，不再阅读任务路径、节点说明和三段式进度。

## 2. 页面结构

加载状态页面居中展示：

1. 小标题：`正在进入下一阶段`。
2. 下一阶段名称，例如：`小说分析`。
3. 大号动态百分比，例如：`62%`。
4. 单条线性进度条。
5. 简短状态文案：`正在准备创作上下文，请稍候…`。
6. 次要操作：`返回当前阶段`。

删除以下内容：

- 当前阶段与下一阶段的双节点路径卡片。
- 任务编号和请求编号的常驻展示。
- “排队校验、准备上下文、开放下一阶段”三段步骤说明。
- 成功后的“立即进入下一阶段”按钮。
- 原型中的“演示失败状态”按钮。

## 3. 进度与自动进入

- 点击“确认当前阶段并进入下一步”后进入加载页，初始为 `0%`。
- `QUEUED` 映射为 `0%–20%`，`RUNNING` 映射为 `21%–99%`，`SUCCEEDED` 映射为 `100%`。
- 静态原型以平滑定时增长演示进度；真实开发必须以后端任务状态为准，禁止用前端计时直接判定成功。
- 到达 `99%` 后等待真实成功状态，不允许提前开放下一阶段。
- 收到 `SUCCEEDED` 后显示 `100%`，停留 500ms，然后自动进入下一阶段。
- 自动进入前，下一阶段状态必须已更新为 `READY`。

## 4. 取消与失败

- 加载中的“返回当前阶段”会取消当前流转任务，并回到原阶段；已确认产物和版本不丢失。
- `FAILED` 时停止进度，不自动跳转；主标题变为“加载失败”，保留失败时的百分比。
- 失败页显示简短错误原因、“重新加载”和“返回当前阶段”。
- “重新加载”创建新任务，百分比从 `0%` 重新开始，并关联原失败任务。
- 详细任务编号、请求编号和技术错误信息保留在任务中心，不在加载页常驻展示。

## 5. 视觉与可访问性

- 百分比是页面唯一视觉焦点，字号建议 56–72px、使用等宽数字特性，避免数值变化造成抖动。
- 进度条宽度建议 320–420px，页面内容保持垂直居中。
- 使用 `role="progressbar"`，同步维护 `aria-valuemin="0"`、`aria-valuemax="100"` 和动态 `aria-valuenow`。
- 状态文案使用 `aria-live="polite"`；失败原因可被屏幕阅读器读取。
- 动效遵循系统“减少动态效果”设置；开启后取消平滑动画，直接更新数值。

## 6. 验收标准

- 七次阶段流转均使用同一个百分比加载页。
- 页面不存在路径卡片、三段步骤、成功确认按钮及演示失败按钮。
- 百分比从 `0%` 更新至 `100%`，且 `SUCCEEDED` 前不得显示 `100%`。
- `100%` 展示 500ms 后自动进入下一阶段，无需二次点击。
- 失败时停止自动跳转，可重新加载或返回。
- 取消和失败均不删除已确认产物。
- 刷新加载页能根据任务状态恢复百分比和操作。
- 八阶段进度、版本、任务中心和下游失效逻辑保持不变。

## 7. PRD 同步范围

更新“阶段确认与过渡进度”章节及验收口径：将三段式进度页调整为百分比加载页，并明确 `100%` 自动进入、失败重试、取消返回和后端状态映射规则。
