# AICP 产品介绍文档设计规格

## 1. 交付目标

生成一份面向意向客户与投资人的中文 Word 产品介绍文档，以真实运行页面截图为主要证据，完整表达 AICP 从模型接入、内容创作、生产协作到资产交付和企业治理的产品价值。

最终仅交付 `.docx`。文档应适合销售会谈、项目介绍、投资沟通及会后转发阅读。

## 2. 受众与叙事原则

- 受众：内容制作公司、MCN、短剧/漫剧团队、企业客户、产业投资人及财务投资人。
- 核心叙事：AICP 不是单点 AI 生成工具，而是将模型能力、内容生产流程、团队治理和资产沉淀连接起来的工业化生产工作台。
- 表达原则：先讲行业问题和业务价值，再讲产品能力；用真实截图支撑关键结论。
- 事实边界：区分已上线能力、当前架构和规划目标；不得将“账号完全统一”等目标态表述为已完成事实。
- 安全原则：截图不得暴露 API Key、Token、密钥、个人联系方式或其他敏感信息。

## 3. 推荐篇幅与章节结构

预计 15–18 页，采用客户价值与投资逻辑双线结构：

1. 封面：AICP 名称、定位语、版本日期。
2. 执行摘要：一句话定位、目标客户、核心价值与平台构成。
3. 行业挑战：工具割裂、模型接入重复、生产过程不可控、团队经验难沉淀、成本与交付难追踪。
4. 产品定位：AI 漫剧与视频内容工业化生产工作台。
5. 双平台架构：8080 内容生产工作台与 3001 模型服务控制台的职责边界和协同关系。
6. 端到端生产闭环：故事种子 → 剧本 → 分镜 → 画布生产 → Agent/SOP 审核 → 资产与交付。
7. 内容创作与项目入口：首页、短剧/长篇/TVC 创作入口。
8. 剧本与分镜生产：剧本创作、剧本仓库及版本化生产能力。
9. 画布与资产生产：画布项目、节点化生产、资产生成与复用。
10. Agent 与工业化 SOP：智能协作、阶段审核、失败恢复和经验沉淀。
11. 企业协作与治理：Workspace、角色权限、审批、预算与审计能力。
12. 模型服务底座：统一模型接入、路由、格式兼容与开发者入口。
13. 模型运营与成本治理：数据看板、渠道、模型、密钥、日志和用量追踪。
14. 核心竞争力：生产闭环、双平台协同、可治理的 AI、资产沉淀与可扩展架构。
15. 客户价值：效率、质量、成本、协作、资产与交付六类收益。
16. 商业与投资价值：平台收入层次、规模化路径、数据/流程/生态壁垒。
17. 部署与合作方式：私有化、企业版、API/模型接入及联合解决方案方向；仅描述代码与权威文档可支持的口径。
18. 结语：从模型到作品，从创作工具到内容生产基础设施。

## 4. 截图计划

### 8080 内容生产工作台

- 首页 `/home`：产品入口、创作模式与模块导航。
- 剧本创作 `/script-gen`：内容生产起点与生成流程。
- 画布项目中心 `/canvas-projects`：可视化生产工作台入口。
- 剧本仓库 `/warehouse`：内容资产与版本管理。
- 资产生成工作台 `/asset-history`：生成资产和任务管理。
- Agent 会话 `/agent` 或 Agent 配置中心 `/agent-config`：智能协作能力。
- 工业化生产 SOP `/sop`：质量控制与流程治理。
- 企业中心 `/enterprise`：组织、权限、审批、预算或审计能力。

### 3001 模型服务控制台

- 数据看板 `/dashboard/models`：模型调用、额度、Token 与性能分析。
- 概览 `/dashboard/overview`：模型服务运营总览。
- 渠道 `/channels`：上游模型渠道与路由管理。
- 模型 `/models/metadata`：模型目录与元数据管理。
- API 密钥 `/keys`：开发者接入能力；仅在无敏感明文时使用。
- 使用日志与任务日志：调用追踪和可观测性。

实际入稿约 10–12 张截图。每张截图需裁掉无关浏览器区域，保证页面标题、核心数据区和关键导航清晰可读；空数据页面以产品结构展示为主，不虚构经营数据。

## 5. 视觉与版式

- 文档类型：高端科技企业产品介绍书。
- 主色：深海军蓝；强调色使用青蓝或紫蓝渐变；正文以深灰为主。
- 页面：A4 纵向，适合屏幕阅读与打印。
- 字体：中文优先使用苹方/思源黑体可用字体，英文与数字使用 Aptos 或 Calibri 回退。
- 封面：大标题、定位语、简洁抽象的双平台/生产链视觉，不堆砌截图。
- 内页：一页一个主要观点；截图配简短标题、说明和价值解读。
- 图表：仅使用一个双平台架构图和一个生产闭环图，避免过度装饰。
- 页眉页脚：AICP 产品介绍、版本日期与页码；封面不显示页码。

## 6. 内容证据与口径

- 产品事实优先来源：`docs/01-core/`、当前运行页面及现有代码行为。
- 当前 8080 与 3001 采用跨端 SSO/JWT 桥及影子用户机制；目标态统一账号不得表述为已完成迁移。
- 不使用未经验证的市场规模、客户数量、收入、效率提升百分比或模型数量作为确定性投资数据。
- 页面营销文案出现的数量指标，如不能从运行状态或权威文档验证，应改写为能力描述或标注为平台支持范围，而非经营成果。
- 商业价值部分以商业模式结构、规模化逻辑和可验证的产品壁垒为主，不编造财务预测。

## 7. 验收标准

- 交付文件可在 Word 正常打开，中文字体、截图、页码和目录显示正确。
- 章节完整，客户和投资人均能在 10 分钟内理解定位、工作流、差异化和合作价值。
- 10–12 张核心页面截图清晰，无敏感信息泄露。
- 所有“现状/规划”表达准确，无账号完全统一等事实性误述。
- 渲染后逐页检查，无文本或图片裁切、重叠、孤行、异常空白页和不可读小字。
- 最终工作区只新增任务规格、生成脚本（如需要）及正式交付物，不改动业务代码。
