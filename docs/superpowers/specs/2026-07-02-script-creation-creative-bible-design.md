# 剧本创作模块完善设计：创作圣经、生态、关系网与写作口径

日期：2026-07-02

状态：方案已确认并完成自检，待用户规格复核

范围：剧本创作模块内部能力完善，以及与分镜、画布、仓库、资产和商业模块的版本契约

设计策略：保留现有平台结构，以“创作圣经”作为剧本模块内部中枢，分期形成可追溯创作闭环

## 1. 背景与现状

平台已经具备内容项目、创作首页、阶段式创作工作台、作品编辑中心、结构化设定、版本、审核、分镜、画布、仓库和资产引用基础，但剧本创作仍主要表现为“按阶段调用 AI 并展示纯文本结果”。现有实现存在以下缺口：

1. 角色、背景、势力、地点和物品虽已有结构化设定基础，但尚未形成覆盖世界规则、制度、资源、能力和关键历史的总体生态。
2. 关系以实体字段或普通 JSON 为主，缺少可编辑图谱、集章时间轴、关系事件和连续性检查。
3. 写作风格尚未成为可执行、可继承、可版本化的约束，无法稳定控制项目叙事基线、角色口吻和单集/单章局部要求。
4. 创作工作台的 AI 生成仍缺少统一、可复现的项目事实快照，容易出现后续生成未使用用户确认设定或修订版本的问题。
5. 上游事实、梗概或大纲变化后，缺少对正文、关系、伏笔、分镜和画布的影响分析。
6. 画布与剧本存在业务耦合，但必须保持独立模块边界，不能由剧本更新直接覆盖画布生产结果。
7. 页面能力、业务实体、权限、版本、异常、审计和验收之间缺少统一的完成口径。

本设计在已确认的“内容项目 + 创作工作台 + 作品编辑中心 + 项目详情 + 仓库”基础上补齐上述能力，不推翻现有平台信息架构。

## 2. 已确认的产品决策

1. 采用“创作圣经中枢”方案，不采用侧栏补丁式堆功能，也不在首期建设全量知识图谱平台。
2. 创作圣经是项目级唯一正式事实源，集中管理总体生态、实体设定、动态关系网、写作口径和连续性台账。
3. 总体生态采用完整模型：时代与世界规则、社会结构、制度禁忌、势力组织、资源体系、能力体系、地点体系和关键历史事件。
4. 长篇默认开放完整能力；短剧精简展示；TVC 映射为品牌、产品、受众、竞品、卖点、禁区和角色表达口径。三种模式共用版本、审计和上下文机制。
5. 动态关系网必须同时具备可编辑关系图和按集/章回放的时间轴。
6. 写作口径采用三级模型：项目级基线 → 角色级口吻 → 单集/单章局部覆盖。下级只覆盖明确字段，其余继承上级。
7. 项目合规禁区和平台硬规则不可被角色级或单元级口径覆盖。
8. AI 只生成候选。候选经用户确认后才能进入正式事实库、生成上下文和下游快照。
9. 事实、结构、正文、改编/TVC、分镜和画布分别独立版本化，上游变更不自动覆盖下游。
10. 画布是独立模块。剧本模块只通过不可变导入快照与画布耦合；剧本变化仅生成差异报告，由用户决定是否创建新快照。
11. 现有创作首页、创作工作台、作品编辑中心、项目详情和仓库继续保留，调整职责和连接方式，不重排平台主导航。
12. 本方案分期交付，不在单个发布批次一次完成所有能力。

## 3. 产品目标与非目标

### 3.1 产品目标

1. 将剧本创作从阶段生成器升级为可持续、可修订、可复现的创作系统。
2. 让生态、设定、关系和写作口径成为结构化、可版本化、可审核的正式资产。
3. 保证所有 AI 生成使用用户已确认的事实和已采用的上游内容版本。
4. 支持长篇项目在大量集章下持续维护人物状态、关系、道具、伏笔、地点和知识边界。
5. 在事实或内容发生变化时，准确定位受影响的结构、正文、分镜和画布快照。
6. 保持剧本、分镜和画布的边界清晰，通过版本契约协作而非共享可变状态。
7. 为权限、费用、审计、异常、迁移、性能和测试提供统一验收口径。

### 3.2 非目标

1. 不将画布并入剧本创作模块。
2. 不在本期实现多人实时共编；使用草稿、乐观锁和冲突合并。
3. 不构建经济、人口、气候演化等超细粒度世界模拟器。
4. 不允许 AI 未经确认直接修改正式事实或用户采用版本。
5. 不允许上游变化自动覆盖分镜、画布、资产采用或市场版本。
6. 不在首期建设通用企业知识图谱平台。
7. 不重做资产市场、交易市场或画布生产内部能力，只定义与其交互的输入输出契约。

## 4. 核心原则

1. **用户确认优先**：AI 结果默认是候选或草稿，不是正式事实。
2. **版本隔离**：各层独立建版本，跨层只引用明确版本 ID。
3. **不可静默覆盖**：上游变化只产生影响和差异，不直接改写下游。
4. **失败透明**：超时、解析失败、权限失败和额度失败进入真实失败状态，不返回示例数据伪装成功。
5. **生成可复现**：每次生成记录实际使用的事实、上游内容、参数、Prompt、模型和规则版本。
6. **按需复杂**：能力完整但界面按模式、阶段和项目成熟度渐进展开。
7. **领域隔离**：每个业务域职责单一，通过稳定契约通信，不共享可变业务 JSON。

## 5. 总体信息架构

### 5.1 页面职责

| 页面 | 核心职责 | 不承担的职责 |
|---|---|---|
| 剧本创作首页 | 新建、上传、最近项目、创作待办 | 复杂筛选、归档和批量管理 |
| 创作工作台 | 梗概、大纲、正文、审核、锁稿和当前单元创作 | 全量项目生命周期管理 |
| 创作圣经 | 作品编辑中心内的核心业务区，负责总体生态、实体设定、动态关系、写作口径和连续性台账 | 正文长文本编辑、画布生产 |
| 作品编辑中心 | 承载作品资料、标签和创作圣经导航、权限、保存与离开保护的统一页面壳层 | 仓库管理和商业操作 |
| 项目详情 | 版本、审核、分镜、生产、商业和流转总览 | 直接修改锁定版本 |
| 剧本仓库 | 查询、筛选、归档、恢复、回收站和生命周期管理 | 修改创作事实 |

### 5.2 页面连接

```text
剧本创作首页
  → 新建/上传/续作
  → 创作工作台
      ↔ 创作圣经
      → 审核与锁稿
      → 项目详情
          → 改编/TVC
          → 分镜 Master
          → 画布导入

剧本仓库
  → 项目详情
  → 显式“继续创作”进入创作工作台
```

创作工作台顶部展示创作圣经健康度、未确认候选数量和当前使用版本。项目详情只读展示锁稿时绑定的圣经快照。仓库只聚合状态，不直接编辑事实。

## 6. 创作圣经功能体系

### 6.1 总体生态

总体生态包含以下受控板块：

| 板块 | 核心字段 | 说明 |
|---|---|---|
| 时代与世界类型 | 时代、世界类型、现实/架空程度、技术水平 | 项目基础坐标 |
| 世界规则 | 规则名称、适用范围、机制、例外、代价 | 可检查正文冲突 |
| 社会结构 | 阶层、身份体系、权利义务、流动规则 | 支撑人物动机与冲突 |
| 制度与禁忌 | 制度、法律、习俗、禁忌、处罚 | 同时支持内容风险提示 |
| 势力与组织 | 目标、结构、成员、资源、领地、盟敌 | 与实体设定和关系网联动 |
| 资源体系 | 资源名称、稀缺度、控制者、用途、获取代价 | 支撑剧情任务 |
| 能力体系 | 能力层级、获得方式、限制、代价、克制 | 防止能力无约束升级 |
| 地点体系 | L0 地点、L1 区域关系、父子层级、交通和控制势力 | 首期不要求可视化地图 |
| 关键历史 | 事件、相对时间、参与者、影响、证据 | 与时间线和当前剧情关联 |

每项生态事实支持名称、摘要、结构化详情、状态、来源、证据、当前版本、引用和归档。正式确认后才进入上下文。

#### 6.1.1 TVC 模式生态映射

TVC（广告/商业短片）项目不涉及虚构世界构建，其生态板块映射到商业表达要素。系统在项目创建时根据模式自动切换可用板块和标签：

| TVC 商业要素 | 映射到的生态板块 | 核心字段 | 说明 |
|---|---|---|---|
| 品牌 | 势力与组织 | 品牌定位、品牌人格、视觉识别约束、品牌声音 | 作为“组织”类型的特化 |
| 产品/服务 | 资源体系 + 物品 | 功能、差异化、使用场景、限制 | 作为“资源”和“物品”类型的合并 |
| 目标受众 | 社会结构 | 人群画像、需求、痛点、触媒习惯 | 简化的人口/行为描述 |
| 竞品 | 制度与禁忌 + 世界规则 | 竞品定位、差异化空间、参照禁区 | 同时生成内容风险提示 |
| 核心卖点 | 世界规则 | 必须传达的信息、支持点、RTB | 不可被 L2/L3 口径覆盖 |
| 品牌禁区 | 制度与禁忌 | 禁用话题、禁用画面、禁用音乐风格 | 等同于平台硬规则，不可覆盖 |
| 角色表达口径 | 实体设定 + 写作口径 L2 | 代言人/角色口吻、人设边界、对受众的表达方式 | 映射到角色级口吻模型 |

TVC 模式下：
- “时代与世界类型”、“关键历史”、“能力体系”板块隐藏；
- “地点体系”替换为“场景/场合”（如家庭、办公室、户外、卖场）；
- 关系网简化为“品牌–产品–受众”三角关系，不展示完整图谱编辑器；
- 所有生态规则的 `rule_type` 使用与长篇相同的枚举值，但 UI 标签替换为 TVC 术语。

### 6.2 实体设定

实体类型继续使用角色、背景、势力、地点和物品五类，并统一扩展以下能力：

- 规范名和别名；
- 摘要和类型化详情；
- 草稿、待补充、已确认、已归档状态；
- 人工、AI 提取、合并、导入等来源；
- 字段级版本和证据；
- 关系引用、内容引用、分镜引用和资产引用；
- 创建、复制、归档、恢复和版本回退；
- 已被版本引用的实体禁止物理删除。

### 6.3 动态关系网

> **技术备注**：关系图谱的前端可视化技术选型（AntV G6 / Cytoscape.js / ECharts）在 P1 启动前通过 2 天技术 Spike 完成。详见 Section 27.3。P0 仅交付数据模型和 API，不引入图谱渲染库。

#### 6.3.1 节点

首期支持人物、势力、地点和物品节点。背景和抽象规则可作为筛选条件或关联事实，不作为首期图节点，避免图谱过度膨胀。

#### 6.3.2 关系字段

每条关系至少包含：

- 来源实体和目标实体；
- 关系类型和方向；
- 强度；
- 公开、秘密或误认状态；
- 当前状态；
- 生效集/章和结束集/章；
- 触发事件和引用内容版本；
- 原文证据和备注；
- 创建来源、修订号和版本。

关系类型由版本化字典管理。系统预置亲属、情感、盟友、敌对、上下级、控制、隶属、占有、守护、交易、债务、知情、误认和自定义类型。不同实体组合限制可用关系类型。

#### 6.3.3 编辑规则

1. 支持图上新增、编辑和结束关系。
2. 删除关系默认转换为结束或归档，不物理删除历史。
3. 关系变化必须绑定集/章或明确的项目时间点。
4. 已被锁稿内容引用的关系变更创建新版本，不改写历史版本。
5. 图谱支持按实体类型、关系类型、集章、状态和公开性过滤。

#### 6.3.4 时间轴与检查

用户可拖动时间轴回放任意集/章时点的关系状态。系统至少检测：

- 关系无起因跳变；
- 互斥关系同时生效；
- 实体尚未登场却建立关系；
- 已结束关系仍被后续正文作为当前关系使用；
- 关系事件的集章顺序冲突；
- 秘密关系被不知情角色提前引用。

### 6.4 三级写作口径

#### 6.4.1 L1 项目级基线

包含叙事视角、时态、语言密度、句长、节奏、幽默度、情绪基调、尺度、平台适配、术语表、禁用表达、内容禁区、旁白规则和对话占比。

#### 6.4.2 L2 角色级口吻

包含称谓、语气、句长、常用词、口头禅、禁用词、知识边界、信息隐瞒、情绪变化、对不同对象的表达差异和示例台词。

#### 6.4.3 L3 单集/单章覆盖

包含本单元视角、节奏、特殊文体、对话限制、临时表达目标、必须出现和不得出现的表达。覆盖必须声明字段和值，不接受整段无结构备注直接替代正式口径。

#### 6.4.4 继承与冲突

1. L3 仅覆盖声明字段，其余继承 L2 和 L1。
2. L2 仅作用于对应角色，不改变项目叙事视角等全局字段。
3. 平台硬规则、合规禁区和项目明确禁区不可被 L2/L3 覆盖。
4. 同级冲突按最新采用版本处理；跨级冲突展示来源和优先级。
5. AI 生成前可预览本次解析后的最终口径，生成任务保存该解析快照。

**不可覆盖字段（`NON_OVERRIDABLE`）：** `hard_bans`（项目明确禁区）、`platform_rules`（平台硬规则）、`compliance_rules`（合规禁区）。这些字段只能由 L1 项目级口径设定，L2 角色级和 L3 单元级的同名键值被忽略并产生冲突记录。此清单由后端 `WritingGuideResolver` 统一定义，前端通过 resolve API 的 `conflicts` 字段获取而非硬编码。

**L1 项目级口径字段定义：**

| 字段 | 类型 | 说明 |
|---|---|---|
| `pov` | string | 叙事视角：`first`/`third`/`omniscient` |
| `tense` | string | 时态：`past`/`present` |
| `pace` | string | 节奏：`fast`/`moderate`/`slow` |
| `language_density` | string | 语言密度：`sparse`/`moderate`/`dense` |
| `tone` | string | 情绪基调 |
| `dialogue_ratio` | number | 对话占比 (0.0–1.0) |
| `hard_bans` | string[] | 项目明确禁区，不可被下级覆盖 |
| `platform_rules` | string[] | 平台硬规则，不可被下级覆盖 |
| `compliance_rules` | string[] | 合规禁区，不可被下级覆盖 |
| `terminology` | object | 术语表，`{"术语":"释义"}` |

**L2 角色级口吻字段定义：**

| 字段 | 类型 | 说明 |
|---|---|---|
| `addressing` | string | 称谓方式 |
| `sentence_length` | string | 句长偏好：`short`/`medium`/`long` |
| `favorite_words` | string[] | 常用词 |
| `catchphrases` | string[] | 口头禅 |
| `knowledge_boundary` | string[] | 知识边界（角色不知道的事） |
| `hidden_information` | string[] | 角色对他人隐瞒的信息 |
| `forbidden_words` | string[] | 禁用词 |
| `tone_variation` | object | 对不同对象的语气差异 |

**L3 单集/单章覆盖字段定义：**

| 字段 | 类型 | 说明 |
|---|---|---|
| `pov` | string | 本单元视角覆盖 |
| `pace` | string | 本单元节奏覆盖 |
| `special_form` | string | 特殊文体（如书信、日记） |
| `dialogue_constraints` | string[] | 对话限制 |
| `must_include` | string[] | 必须出现的表达/元素 |
| `must_avoid` | string[] | 不得出现的表达/元素 |

### 6.5 连续性台账

每个锁稿集/章生成连续性快照，至少包含：

- 人物位置、生命/健康、情绪、身份和持有信息；
- 关系变化和知情范围；
- 道具归属、状态和位置；
- 伏笔埋设、强化、误导、回收和废弃状态；
- 关键事件及相对时间；
- 场景状态和已发生变化；
- 已绑定的角色、场景、物品、声音和风格资产版本。

下一单元默认使用上一个锁稿快照。用户可以选择更早快照作为分支起点，但必须创建派生链。

## 7. 创作工作台设计

### 7.1 三栏结构

| 区域 | 内容 |
|---|---|
| 左侧阶段轨道 | 故事种子、人物与生态、梗概、大纲、正文、审核、锁稿/去向；按模式自适应展开 |
| 中央创作区 | 结构化编辑器、正文编辑器、AI 操作、结果对比、采用版本、问题定位 |
| 右侧上下文区 | 当前圣经版本、相关人物与关系、本单元口径、连续性警告、影响范围和版本历史 |

顶部状态区展示项目模式、内容状态、圣经健康度、未确认候选、保存状态、AI 任务状态和唯一主操作。

### 7.2 生成交互

生成前展示：

- 使用的上游内容版本；
- 使用的圣经和口径版本；
- 当前集/章连续性起点；
- 模型和生成模式；
- 预计费用和额度；
- 存在的硬阻断与软警告。

生成后：

- 结果进入候选版本，不覆盖当前编辑稿；
- 支持全文采用、按段采用、对比和放弃；
- 标注与当前事实或口径的冲突；
- 采用后创建内容版本并记录派生链；
- 生成失败保留用户草稿和任务诊断信息。

## 8. AI 候选与人工确认

### 8.1 候选来源

候选可来自人工录入、上传文稿提取、已有版本重新提取、AI 补全和冲突修复建议。

### 8.2 候选结构

每个候选包含类型、字段值、证据位置、证据片段、字段级置信度、匹配的正式实体、匹配原因、冲突类型、模型、Prompt 版本和来源版本。

### 8.3 确认流程

```text
选择来源和目标类型
→ 创建幂等提取任务
→ 生成候选
→ 用户逐字段选择新增、合并、保留原值或采用新值
→ 预览影响范围
→ 确认应用
→ 事务写入正式新版本
→ 刷新上下文快照并发布影响分析事件
```

未经确认的候选不进入正式查询、生成上下文、质量闸门、分镜或画布快照。

## 9. 版本、派生与影响分析

### 9.1 版本边界

以下对象分别版本化：

- 创作圣经；
- 生态事实和实体设定；
- 关系及关系事件；
- 写作口径及解析快照；
- 故事种子、梗概、大纲、正文；
- 改编脚本和 TVC 脚本；
- 分镜 Master；
- 画布导入快照；
- 生成资产和采用资产。

正式版本不可原地修改。草稿允许更新，但提交、确认、采用、锁稿或导入时必须创建不可变版本。

### 9.2 生成上下文快照

上下文组装器按模式、阶段、当前集章、相关实体和 Token 预算裁剪事实。快照记录：

- 项目参数版本；
- 创作圣经版本；
- 采用的上游内容版本；
- 相关实体和关系版本；
- 写作口径解析结果；
- 连续性起点；
- 平台和合规规则版本；
- 裁剪策略和被省略项摘要。

### 9.3 影响分析

正式事实、关系、口径、梗概或大纲变化后创建影响报告，标记：

- 直接受影响的集章和字段；
- 可能受影响的后续集章；
- 关系和连续性冲突；
- 未回收伏笔和时间线变化；
- 过期的分镜 Master；
- 过期的画布导入快照；
- 建议动作：局部修订、重生成、忽略、重新审核或创建新快照。

影响报告只提供决策依据，不自动改写任何下游版本。

## 10. 审核与质量闸门

### 10.1 检查维度

1. 创作圣经事实一致性；
2. 人物动机和知识边界；
3. 关系连续性；
4. 时间线和地点可达性；
5. 道具归属和状态；
6. 伏笔埋设与回收；
7. 写作口径和角色口吻；
8. 钩子、冲突升级和节奏；
9. 画面可表达性和生产成本；
10. 平台、版权和内容安全规则。

钩子 Agent、编导 Agent 和导演 Agent 保留，并增加事实一致性和口径检查。所有问题必须包含严重级别、定位、证据、规则来源和建议动作。

### 10.2 闸门等级

| 等级 | 行为 |
|---|---|
| 硬阻断 | 不允许提交、锁稿、导入或上架，必须修复或由具备权限的 Reviewer 风险放行 |
| 软警告 | 允许继续，但要求用户确认已知风险 |
| 提示 | 不阻断，仅提供优化建议 |

审核、锁稿、分镜、画布生产准入和商业上架使用不同规则集与规则版本。

## 11. 分镜与独立画布模块契约

### 11.1 正向流向

```text
锁稿内容版本
→ 可选改编/TVC 版本
→ 分镜 Master A/B/C
→ 生产准入
→ 画布导入快照
→ 独立画布生产
```

分镜不是内容创作完成条件。用户只有选择制作分镜或进入画布生产时才触发相应准入。

### 11.2 画布导入快照

导入快照至少包含：

- 锁稿内容版本；
- 分镜 Master 版本；
- 创作圣经版本；
- 关系时间点和连续性快照；
- 角色、地点、物品、声音和风格资产引用；
- 平台、视觉和内容规则版本；
- 风险放行记录；
- 资产成熟度和缺失项；
- 导入参数、操作者和时间。

### 11.3 反向流向

画布向内容项目回传生产状态、采用资产、质量结果和导出结果，不直接修改剧本事实。剧本、圣经或分镜更新后：

1. 系统计算与当前画布快照的差异；
2. 项目详情显示受影响节点和资产；
3. 用户选择忽略、局部处理或创建新画布导入快照；
4. 旧快照和既有生产结果永久保留；
5. 新旧快照不得共享可变节点状态。

## 15. 状态模型

### 15.1 创作圣经

```text
draft → reviewable → confirmed → superseded
                     ↘ archived
```

- `draft`：允许编辑，不进入正式上下文；
- `reviewable`：候选整理完成，等待确认。通过“提交审核”操作从 `draft` 转换（P0 提供 API，UI 在 P1 候选确认流程中交付）；
- `confirmed`：正式版本，可进入生成上下文；
- `superseded`：已被新确认版本替代，仍可追溯；
- `archived`：项目主动归档，不作为当前事实。P0 提供 `POST /{id}/creative-bible/versions/{versionId}/archive` 端点，已确认版本归档前需确认无下游依赖。

### 15.2 AI 候选批次

```text
queued → running → review_pending → applying → applied
   ↘ failed / cancelled       ↘ conflicted
```

`failed`、`cancelled` 和 `conflicted` 必须保留原因及可恢复操作。

### 15.3 影响报告

```text
open → acknowledged → resolved
  ↘ ignored（必须记录理由）
```

### 15.4 关系事件

关系事件使用 `planned`、`effective`、`superseded`、`cancelled`。历史 `effective` 事件不可删除，只能由新事件结束或替代。

唯一约束：`(project_id, bible_version_id, scope_type, scope_id, version_no)`。口径版本归属于特定圣经版本，同一圣经版本内同作用域可有多版修订。

### 16.6 `writing_guide_resolutions`

保存某次生成解析后的最终口径，字段包含 `generation_job_id`、项目/角色/单元口径版本、`resolved_json`、冲突和覆盖来源。

> P0 不创建此表。P1 通过独立 migration 交付，届时 `snapshot_json` 包含人物位置、健康、关系变化、道具归属、伏笔状态和关键事件。

### 16.8 `generation_context_snapshots`

保存生成实际使用的项目参数、事实、关系、口径、连续性、平台规则、裁剪策略和摘要，关联生成任务并保持不可变。

### 16.9 `project_impact_reports`

建议字段：`id`、`project_id`、`trigger_type`、`trigger_version_id`、`baseline_version_id`、`status`、`severity`、`affected_items_json`、`suggested_actions_json`、`resolved_by`、`resolved_at`。

### 16.10 数据约束

1. 正式版本使用项目内单调递增版本号和唯一约束。
2. 跨项目外键必须在服务层和数据库约束层同时校验。
3. `details_json`、`guide_json` 和快照 JSON 必须由版本化 JSON Schema 校验。P0 阶段在服务层通过 Java POJO + `@Valid` 校验关键字段（`rule_type`、`scope_type`、`status`），完整 JSON Schema 版本化在 P3 治理阶段通过 Schema Registry 交付。
4. 关系的起止单元必须属于同一项目且顺序合法。
5. 所有正式确认和导入操作使用幂等键。
6. 被引用的实体、关系和版本禁止物理删除。
7. `ecosystem_rules.rule_type` 由服务层白名单校验，合法值为 `era_world`、`world_rule`、`social_structure`、`institution_taboo`、`faction_organization`、`resource_system`、`ability_system`、`location_system`、`key_history`，TVC 模式下增加 `brand`、`product_service`、`target_audience`、`competitor`、`core_selling_point`、`brand_taboo`、`character_expression`。
8. `project_writing_guides.scope_type` 由服务层白名单校验，合法值为 `project`、`character`、`content_unit`。`scope_type=project` 时 `scope_id` 必须为 `0`；`character` 和 `content_unit` 时 `scope_id` 必须为正整数且对应实体存在。

## 18. 事件与状态投影

关键事件包括：

**P0 事件：**
- `CREATIVE_BIBLE_CONFIRMED` — 圣经版本确认；
- `PROJECT_FACT_CHANGED` — 生态规则或实体设定变更；
- `WRITING_GUIDE_CONFIRMED` — 写作口径确认；
- `CONTEXT_SNAPSHOT_CREATED` — 生成上下文快照创建；
- `CONTENT_VERSION_ADOPTED` — 内容版本被采用。

**P1 事件：**
- `RELATION_EVENT_APPLIED` — 关系事件生效；
- `CONTENT_VERSION_LOCKED` — 内容版本锁稿；
- `IMPACT_REPORT_CREATED` — 影响报告生成。

**P2 事件：**
- `STORYBOARD_MASTER_LOCKED` — 分镜 Master 锁定；
- `CANVAS_IMPORT_SNAPSHOT_CREATED` — 画布导入快照创建；
- `CANVAS_PRODUCTION_STATUS_CHANGED` — 画布生产状态变更。

事件通过事务 Outbox 发布，消费者使用事件 ID 和业务幂等键去重。仓库、项目详情和画布状态采用最终一致投影；关键写操作完成后 API 返回权威源状态，不依赖投影即时更新。

## 19. 异常处理与恢复

| 场景 | 系统行为 | 用户恢复方式 |
|---|---|---|
| AI 超时/失败 | 任务标记失败，保留草稿、输入快照和费用状态 | 重试或更换模型 |
| 结构化解析失败 | 保存原始输出和解析错误，不创建候选 | 重试解析或人工录入 |
| 保存冲突 | 返回 409 和服务器版本摘要，保留本地草稿 | 对比、合并或另存版本 |
| 候选应用冲突 | 批次进入 conflicted，不部分写入正式库 | 重新审核冲突字段 |
| 上下文过长 | 按裁剪规则生成摘要并明确列出省略项 | 调整范围或拆分生成 |
| 额度不足 | 生成前阻断，不创建运行任务 | 充值、调整模型或缩小范围 |
| 画布导入校验失败 | 不创建正式导入快照 | 修复缺失分镜/资产/权限后重试 |
| 状态投影延迟 | 展示同步中，权威写状态不回退 | 自动重放事件或人工刷新 |
| 旧项目映射失败 | 旧入口保持只读并记录迁移失败 | 管理员修复映射后重试 |

任何失败都不得用固定示例内容、空成功响应或错误状态回退伪装成功。

### 19.1 错误码清单

| 错误码 | 含义 | 触发场景 |
|---|---|---|
| `PARAM_INVALID` | 请求参数不合法 | 必填字段缺失、枚举值非法、JSON 格式错误 |
| `DATA_NOT_FOUND` | 目标数据不存在 | 圣经版本、生态规则、口径、实体设定版本缺失 |
| `PERMISSION_DENIED` | 无操作权限 | Viewer 尝试写入、非 Owner 尝试管理成员 |
| `VERSION_CONFLICT` | 修订号冲突 (HTTP 409) | 并发保存导致乐观锁失败 |
| `BIBLE_NOT_CONFIRMED` | 圣经未确认 | 生成任务要求已确认圣经但当前项目无确认版本 |
| `BIBLE_IMMUTABLE` | 圣经不可修改 | 对 `confirmed`/`superseded`/`archived` 版本执行写操作 |
| `CANDIDATE_CONFLICT` | 候选应用冲突 | 目标实体已被其他操作修改 |
| `EXTRACTION_FAILED` | AI 提取/解析失败 | 结构化解析失败，原始输出已保存 |
| `QUOTA_EXCEEDED` | 额度不足 | 生成前阻断，不创建运行任务 |
| `SYSTEM_ERROR` | 系统内部错误 | 序列化失败、数据库异常、事件发布失败 |

所有错误响应包含 `code`、`message`、`details`（可选，定位具体字段或冲突来源）和 `request_id`（用于审计追溯）。

## 20. 性能与规模

### 20.1 性能 SLI（Service Level Indicators）

| 操作 | 目标延迟 (P95) | 适用项目规模 | 测量方式 |
|---|---|---|---|
| 创作工作台首屏加载 | < 2s | 100 章项目 | 浏览器 Performance API，不含正文内容加载 |
| 圣经概览页加载 | < 800ms | 任意 | API `/creative-bible` + `/creative-bible/health` 并行请求 |
| 生态规则列表（含筛选） | < 500ms | 50 条规则 | 分页 20 条/页，索引 `(project_id, bible_version_id)` |
| 写作口径解析预览 | < 300ms | 3 级口径（项目 + 3 角色 + 单元） | 纯 Java 内存计算，不查库 |
| 上下文组装（含快照持久化） | < 500ms | 100 章项目 | 圣经快照已在内存中，裁剪为 Token 预算 |
| 关系图谱增量加载 | < 1s | 100 节点 / 200 边 | 按集章范围过滤，增量传输 |
| 影响分析（异步） | < 30s | 100 章项目 | 后台任务，通过事件通知结果 |
| 圣经确认（含快照生成） | < 3s | 20 条生态规则 + 50 个实体设定 | 单事务内完成 |

### 20.2 规模策略

1. 关系图按可见节点、实体类型、集章范围增量加载，首屏不加载完整长篇图谱。
2. 长篇内容单元、关系事件、连续性快照和版本历史必须分页。
3. 上下文组装缓存以项目、圣经版本、单元和规则版本为键；事实确认后精确失效。
4. 影响分析和全量连续性检查使用异步任务，当前单元局部检查允许同步返回。
5. 大项目设置节点、边、单次提取字符数和并发任务上限，超限时提供拆分策略。
6. 100 章项目应能在不加载全量正文的情况下打开工作台、关系网和连续性列表。

| 连续性快照数 | N/A (P1 交付) | 10,000/项目 | 自动归档 180 天前的旧快照 |

## 21. 数据迁移与兼容

1. 保留旧 `scripts` 和旧链接兼容层，新能力以 `content_project` 为主对象。
2. 现有 `content_project_profiles` 映射项目资料；`project_setting_entities` 和版本表作为实体设定基础，不另建第二套角色/地点 CRUD。
3. 现有角色、背景、势力、地点和物品数据回填首个创作圣经草稿版本；未经用户确认不自动标记为正式事实。
4. 旧关系 JSON 提取为候选关系，用户确认后进入正式关系表。
5. 旧自由文本风格配置保留为导入证据，解析为口径候选，不直接变成正式口径。
6. 迁移采用回填、双读校验、主链路切换、兼容只读和清理五步，不长期双写两套正式事实。
7. 每一步提供数据量、失败量、重复量和抽样一致性报告，并保留回滚开关。

## 22. 分期交付

### P0：基础闭环

- 创作圣经壳层和健康度；
- 总体生态结构化表单；
- 现有实体设定纳入圣经；
- 三级写作口径及解析预览；
- 圣经版本和生成上下文快照；
- 现有梗概、大纲和正文生成接入快照；
- 权限、审计、失败透明和基础迁移。

验收：任一新生成内容都能追溯到明确的上游版本和圣经快照；未经确认候选不进入上下文。

### P1：关系与质量

- 可编辑关系图；
- 集章时间轴和关系事件；
- 连续性台账；
- 事实、关系、知识和口径冲突检查；
- 影响报告和局部修订建议。

验收：关系可按集章回放；事实变化可定位受影响集章；冲突可定位证据和规则。

### P2：下游契约

- 分镜引用明确内容和圣经版本；
- 生产准入；
- 画布导入快照预览和创建；
- 剧本/圣经/分镜到画布的差异报告；
- 画布状态和采用资产回执投影。

验收：上游变化不覆盖既有画布；用户可预览差异并创建新快照；旧快照可追溯。

### P3：深化治理

- 模板和字典治理；
- 高级协作和审批策略；
- 大项目性能优化；
- 商业和导出准入；
- 高级指标与运营分析。

验收：配置规则版本化生效；大项目性能达到目标；商业导出能追溯来源和授权。

## 25. 验收标准

整体能力完成必须同时满足：

1. 任一 AI 生成版本可追溯到明确的上游内容、圣经、口径、连续性、参数、Prompt、模型和规则版本。
2. 未经确认的 AI 候选不会进入正式事实、生成上下文、分镜或画布快照。
3. 总体生态完整覆盖已确认板块，并能被结构和正文生成消费。
4. 关系网可编辑、可按集/章回放，关系变化可定位事件、证据和内容版本。
5. 三级写作口径按继承规则生效，冲突和偏离能定位到字段和文本。
6. 事实或内容变化产生影响报告，不自动改写任何下游版本。
7. 剧本、分镜和画布通过不可变快照协作，旧画布快照和生产结果保持不变。
8. 权限、审计、费用、状态、异常、配置版本、迁移和性能均有自动化测试或可重复验收步骤。
9. 刷新、重进、失败重试、并发保存和旧项目迁移不丢草稿、不重复创建正式版本、不伪成功。
10. 每个业务域具备职责、实体、状态、输入、输出、权限、版本、异常、事件、API、页面入口、测试和验收口径，缺少任一项不得标记为完成。

## 27. 后续能力规划

以下能力不在 P0–P3 范围内，但设计时已预留扩展点。在对应的分期执行计划中补充详细规格。

### 27.1 圣经内搜索

**目标分期**：P3

- 支持按名称、类型、标签、状态、创建时间对生态规则、实体设定、关系和写作口径做全文检索。
- 搜索结果按实体类型分组，高亮匹配片段。
- 预留扩展点：`ecosystem_rules` 和 `project_setting_entities` 的 `name`、`summary` 和 JSON 内容建立全文索引（MySQL `FULLTEXT` 或 Elasticsearch）。

### 27.2 批量操作

**目标分期**：P1（候选确认）/ P3（其他）

- 候选确认：支持“全部采用”、“全部忽略”、“按置信度筛选后批量采用”。
- 生态规则：支持批量归档、批量修改状态。
- 导出：支持批量导出选定集章的圣经快照为 Markdown/PDF。
- 预留扩展点：候选表的 `status` 和 `confidence` 字段已支持批量更新。

### 27.3 关系图谱可视化技术选型

**目标分期**：P1 执行前完成技术验证

- **候选方案**：ECharts（力导向图）、AntV G6、Cytoscape.js、D3-force。
- **选型标准**：100 节点 + 200 边流畅渲染（60fps 拖拽）、缩放和平移、节点/边自定义样式、支持 Vue 3 集成、包体积 < 200KB gzipped、中文文档和社区支持。
- **推荐**：AntV G6（图可视化专用库，内置力导向和层级布局，支持自定义节点和边，Vue 3 集成成熟）或 Cytoscape.js（学术级，布局算法丰富）。
- P0 不引入图谱库。P1 启动时完成 2 天技术 Spike，产出可运行的 `RelationGraph.vue` 原型和选型结论。

### 27.4 圣经导出与分享

**目标分期**：P3

- 导出格式：Markdown（Git 友好，可版本化）、PDF（正式审阅）、JSON（机器可读，供外部工具消费）。
- 导出内容：用户可选择导出范围（全部 / 当前版本 / 指定集章快照）。
- 分享：生成只读分享链接 + 过期时间 + 密码保护（可选）。分享页不依赖平台登录态。
- 预留扩展点：`creative_bible_versions.snapshot_json` 已包含完整事实快照，导出即序列化。

### 27.5 通知机制

**目标分期**：P3

- 触发场景：候选待确认、影响报告待处理、圣经版本被替代、连续性冲突检出、画布生产完成。
- 通知渠道：站内信（`notification` 表）、邮件（可选，企业配置）、WebSocket 实时推送（前端 `useNotification` composable）。
- 通知聚合：同一项目的同类通知在 5 分钟内合并为一条。
- 预留扩展点：事件 Outbox 已包含所有关键事件的 `project_id` 和 `user_id`，通知消费者可直接消费。

### 27.6 无障碍与暗色模式

**目标分期**：P3

- 暗色模式：基于 CSS 变量实现，与系统偏好同步。所有生态规则表单、图谱画布、口径编辑器支持暗色主题。
- 键盘导航：Tab 切换焦点、Enter 确认、Escape 关闭弹窗、Space 勾选。图谱编辑器支持键盘平移（方向键）和缩放（+/-）。
- 屏幕阅读器：表单标签关联 `aria-labelledby`、状态变化使用 `aria-live` 区域、图谱节点提供 `aria-label`。
- 色彩对比度：正文文本 ≥ 4.5:1、大文本 ≥ 3:1（WCAG AA）。

### 27.7 图谱可视化交互规格（P1 前置）

**目标分期**：P1 执行时详细设计

- 布局模式：力导向（默认，展示全局关系）、层级（展示势力隶属）、环形（展示角色围绕主角的关系）。
- 节点样式：按实体类型区分形状和颜色（人物=圆形、势力=菱形、地点=方形、物品=三角形）。节点大小反映关系数量。
- 边样式：按关系类型区分颜色和线型（亲属=实线、敌对=虚线、秘密=点线）。关系强度映射为线宽。
- 交互：悬停高亮关联节点和边、单击选中并展开详情侧栏、双击进入实体编辑、右键菜单（编辑关系/查看历史/跳转集章）。
