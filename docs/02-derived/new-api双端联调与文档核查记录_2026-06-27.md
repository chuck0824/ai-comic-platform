## 核查报告

**问题：5处（高 2 / 中 2 / 低 1）**

| # | 类别 | 位置 | 问题 | 严重 |
|---|---|---|---|---|
| 1 | 运行故障 | `3001/console` | 经典主题数据看板初始化 VChart 时出现 `createCanvas` 空引用，触发全页错误边界 | 高 |
| 2 | 架构口径 | 账号体系 | 现有 new-api 本地账号与 AICP 账号独立，不符合“账号共用、功能不同”要求 | 高 |
| 3 | 文档冲突 | new-api 对接规划 | 原文写为“new-api 用户体系自建”，与统一账号事实源要求冲突 | 中 |
| 4 | 配置一致性 | 服务地址 | new-api 状态仍显示默认 `http://localhost:3000`，与本地 `3001` 约定不一致 | 中 |
| 5 | 版本标识 | new-api 页面 | 本地源码构建显示 `v0.0.0`，未注入上游版本号 | 低 |

## 调试结论

| 检查项 | 结果 |
|---|---|
| new-api 服务 | 独立 Go 进程监听 `3001` |
| AICP 用户端 | 独立 Java 进程监听 `8080` |
| new-api 数据 | 使用 `new-api/data/new-api.db`，与 AICP 数据隔离 |
| 初始化状态 | 已完成，存在本地 `admin` 初始化账号 |
| 经典主题 | 数据看板不可用，错误为 `Cannot read properties of undefined (reading 'createCanvas')` |
| 新版主题 | 已切换成功，主页和新版登录页可正常渲染 |
| 登录状态 | 主题切换后旧前端登录态失效，需要重新登录新版前端 |

## 本次处理

1. 保留 `3001` 作为 new-api 管理端和模型网关，`8080` 作为 AICP 用户端。
2. 将 new-api 前端从经典主题切换为新版主题，绕开经典主题 VChart 初始化故障。
3. 修订核心文档，明确“账号共用、功能隔离、数据分域”的目标架构。
4. 明确 `user-svc` 为账号事实源，new-api 用户只作为配额、令牌和账单影子记录。
