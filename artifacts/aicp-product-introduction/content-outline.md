# AICP 产品介绍文案大纲

## 1. 封面

**AICP**  
AI 漫剧与视频内容工业化生产工作台

从模型能力到可交付内容，让创作团队像一条可治理、可复用、可扩展的产线运行。

客户与投资人介绍版｜2026 年 8 月

## 2. 执行摘要

AICP 面向漫剧、短剧、长篇内容与 TVC 团队，把剧本创作、分镜生产、画布编排、AI 资产生成、Agent 协作、质量准入、企业治理和模型服务连接成一套生产系统。平台由两部分组成：8080 内容生产工作台承载创作与交付流程；3001 模型服务控制台承载模型接入、渠道路由、调用观察与成本治理。

对客户，AICP 的价值是减少工具切换，让创意、任务、版本、资产和成本落在同一个可追踪体系中。对投资人，AICP 的意义是从一次性生成工具升级为深入业务流程的内容生产基础设施，收入与壁垒可从席位、用量、企业治理和生态交易多层形成。

## 3. 行业挑战

1. 工具割裂：文本、图片、视频、配音与资产分散在不同平台，项目上下文反复搬运。
2. 生产不可控：生成结果很多，但采用版本、失败原因、成本和交付状态难追踪。
3. 经验难复制：导演、编剧和制片人的判断停留在个人经验，难固化为团队流程。
4. 模型接入重复：多供应商、多协议、多计费口径增加研发与运维负担。
5. 企业治理缺位：权限、预算、审批、审计和资产边界无法覆盖 AI 生产链。

## 4. 产品定位

AICP 是融合无限画布、节点工作流、分镜生产、资产库、批量生成、素材交付、工作流模板与 Agent/Skill 自动执行的一站式内容生产平台。它的产品边界是“生产工作台”，重点在创作决策、生成编排、质量控制和素材交付，不定位为视频剪辑器或多轨时间轴工具。

## 5. 双平台架构

- 内容生产工作台（8080）：服务创作者、制片与企业团队，负责内容项目、剧本、分镜、画布、资产、Agent、SOP 与企业业务。
- 模型服务控制台（3001）：服务开发者、运营与管理员，负责模型目录、渠道、路由、额度、调用日志与成本可见性。
- 协同方式：内容生产端提出生成任务，模型服务端完成统一调用与计量，结果回到资产和任务体系沉淀。
- 当前账号边界：两端通过短时 SSO/JWT 桥与用户映射协同；完整统一账户仍属于迁移目标。

## 6. 端到端生产闭环

故事种子 → 剧本与世界观 → 分集与分镜 → 画布节点编排 → 多模型生成 → Agent/SOP 审核 → 采用版本与资产沉淀 → 素材包交付。

闭环的核心不是“多生成一次”，而是让每一个结果都能回答：从哪里来、用了什么模型、花了多少、为什么被采用、是否通过质量门槛、最终交付到哪里。

## 7. 内容创作入口

工作台首页把短剧、长篇与 TVC 放在同一生产入口，并连接最近创作、画布生产、内容与交易。对于团队而言，内容类型可以不同，但项目、任务、资产和治理的底层方式保持一致。

## 8. 剧本与内容资产

剧本创作提供快速创作、专业分步创作、文稿导入与 TVC 创作。剧本仓库不只是文件列表，而是以草稿、审核、锁稿、生产、完成与归档等状态连接内容决策和后续生产，形成可追踪的内容资产生命周期。

## 9. 画布生产

画布项目中心承接剧本与分镜之后的可视化生产。节点化方式让角色、场景、分镜、图片、视频与生成任务在同一空间被组织、复用和批量执行。平台强调“生产编排与素材交付”，而非多轨剪辑。

## 10. 资产工作台

生成历史、任务状态、采用结果和失败原因统一进入资产工作台。资产可按项目与类型组织，并与画布双向流转。真实页面已经展示排队中、失败、模型信息与错误原因等状态，说明平台不只呈现成功结果，也把异常纳入生产管理。

## 11. Agent 与 SOP

Agent 配置中心把角色边界、工具权限、上下文策略、输出协议和模型参数从业务代码中解耦，并通过版本、绑定、试跑和执行快照支持复用。工业化 SOP 以项目为单位管理生产准入与返工工单，权威规格进一步定义六个生产 Gate、规则引擎、审计返工和失败恢复。

这使团队经验有机会从“师傅带徒弟”变成“可配置、可验证、可回滚的组织能力”。

## 12. 企业协作与治理

企业工作台规划并承载 Workspace、组织成员、角色权限、统一审批、采购预算和跨域审计。3001 负责账户、工作区、权限、余额和 AI 限额等账户域能力，8080 负责内容业务、预算治理规则与审批投影；关键命令回到各业务域执行。

当前企业概览接口仍需继续联调，因此本节不使用异常页面截图，也不将目标态写成已全面上线。

## 13. 模型服务底座

模型服务控制台把多供应商接入转化为统一目录、统一协议入口和可管理的渠道。渠道可以配置状态、类型、路由与重试；模型元数据覆盖供应商、端点、标签、授权包和部署信息。内容团队由此不必在每个生产模块重复对接模型。

## 14. 模型运营与成本治理

数据看板面向调用量、额度、Token、RPM、TPM、消耗分布和趋势；使用日志追踪同步请求的渠道、用户、模型、Token 与费用；任务日志追踪异步生成任务的编号、运行时间与状态。三个层次共同回答“谁在何时调用了什么、结果如何、成本多少”。

## 15. 核心竞争力

1. 生产闭环：从创意到交付，不停留在单次生成。
2. 双平台协同：内容生产与模型治理分层，业务体验和技术底座同时演进。
3. 可治理的 AI：Agent、SOP、审批、预算和审计把生成纳入企业规则。
4. 资产沉淀：版本、任务、提示、结果与采用关系持续形成可复用资产。
5. 可扩展架构：模型、渠道、Agent、工作流与业务模块保持清晰边界。

## 16. 客户价值

- 效率：统一入口减少跨工具切换与重复录入。
- 质量：分镜、版本、生产 Gate 与返工机制让审核有依据。
- 成本：模型路由、用量与日志让生成成本可见、可定位。
- 协作：项目、Workspace、角色与任务形成共同事实源。
- 资产：角色、场景、镜头和生成记录可复用，而非散落在个人文件夹。
- 交付：采用版本、质量状态与素材清单可追踪，降低交接风险。

## 17. 商业与投资价值

潜在收入结构包括个人/团队席位、模型调用与增值服务、企业治理与私有化部署、开放 API 及资产/内容交易服务。规模化路径从创作者工具切入，向团队生产系统、企业控制面和生态交易延展。

关键壁垒并非单一模型，而是长期沉淀的生产流程、项目上下文、质量规则、资产关系、任务与成本数据，以及对多模型供给的持续适配。模型能力越丰富，统一编排和治理的价值越高；项目使用越深入，流程与资产迁移成本越高。

## 18. 部署、合作与结语

合作方向包括团队版/企业版工作台、私有化部署、模型与渠道接入、内容生产流程共建、API 集成和联合解决方案。具体交付范围应结合客户流程、合规要求、模型供应和系统集成边界确认。
